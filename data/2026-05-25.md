### [1] [Step in Tine: Forking Processes in Functional Choreographies](https://arxiv.org/abs/2605.23031)
*Ashley Samuelson,Andrew K. Hirsch,Ethan Cecchetti*

Main category: cs.PL

TL;DR: 本文提出了λpitchfork，这是首个支持进程分叉的函数式编舞语言，在保证无死锁的同时允许动态生成新进程，支持负载均衡和分治等实际应用。


<details>
  <summary>Details</summary>
Motivation: 传统的并发编程技术需要为每个参与者分别编写程序，而编舞编程虽然可以集中编写再编译为个体程序，但难以处理进程分叉这一核心原语。本文旨在填补这一空白。

Method: 提出了编舞分叉演算λpitchfork，这是首个支持进程分叉的函数式编舞语言。该语言允许程序动态决定何时生成新进程、新进程执行什么任务以及谁与它们通信。

Result: λpitchfork在保证无死锁的同时，支持进程的动态分叉，能够实现负载均衡和并行分治等实际应用。

Conclusion: 通过λpitchfork，编舞编程成功扩展至支持进程分叉，既保留了无死锁保证，又增强了表达实际并发模式的灵活性。

Abstract: Traditional concurrent-programming techniques require programmers to painstakingly write programs for each participant in a concurrent system. Choreographic programming, in contrast, allows a programmer to write one centralized program and compile it to individual programs. This approach simplifies critical properties like deadlock freedom, but it complicates forking new processes, a core primitive in concurrent programming. This work addresses that gap with the choreographic fork calculus $λ{\pitchfork}$, the first functional choreographic language with process forking. $λ{\pitchfork}$ provides a deadlock-freedom guarantee while allowing programs to dynamically determine when to spawn new processes, what they will do, and who will communicate with them. In doing so, it supports practical applications like load balancers and parallel divide-and-conquer.

### [2] [JEDI: Java Evaluation of Declarative and Imperative Queries](https://arxiv.org/abs/2605.23543)
*Filippo Schiavio,Walter Binder*

Main category: cs.PL

TL;DR: 本文提出 JEDI 基准测试套件，通过将 SQL 基准测试自动转换为 Java 基准测试，用于分析 Java Stream API 的性能差异、识别低效代码结构，并为开发者提供最佳实践建议。


<details>
  <summary>Details</summary>
Motivation: 目前缺乏专门针对 Java Stream API 的基准测试，导致研究人员和开发者难以优化 Stream API，同时也难以分析流式计算的性能表现来指导开发者编写高效代码。

Method: 通过将 SQL 基准测试自动转换为 Java 基准测试生成 JEDI 基准套件；代码生成器支持为同一查询生成多种实现（包括基于流和命令式两种方式）；重点分析不同并行化策略的性能差异。

Result: 生成了涵盖多种实现的基准测试套件；揭示了不同并行化策略在流处理中的性能差异；识别了低效的代码结构并提出了替代方案；建立了命令式代码作为基线，为 Stream API 优化提供参考。

Conclusion: JEDI 基准套件为 Java Stream API 提供了系统的性能评估工具，能够帮助开发者和 Java 类库实现者识别最佳实践并优化 API。

Abstract: The Java Stream API aims at increasing developer productivity thanks to an easy-to-read declarative syntax to express computations. It also simplifies parallel computing, providing a high-level abstraction on top of common parallelization aspects. Unfortunately, there is a lack of benchmarks specifically targeting stream-based applications. Such a lack of benchmarks makes it difficult for researchers and developers of the Java class library to optimize the Stream API. Moreover, in the absence of dedicated benchmarks, it is difficult to analyze the performance of streams to suggest developers how to write efficient code using the API.
  In this work we present JEDI, a benchmark suite that targets the Stream API. JEDI is automatically generated by converting SQL benchmarks into Java benchmarks. Our code generator supports targets different implementations (both stream-based and imperative) for the same query. The ultimate goal of our benchmark suite -- and the main contribution of this work -- is to analyze the performance of the different implementations to spot inefficient code structures and better alternatives, suggesting best practices to Java developers. Among the multiple implementations we generate, we focus on different parallelization strategies and explain the most efficient parallelization strategies based on characteristics of the processed data. Finally, the code generation producing imperative code defines of a baseline that can guide researchers and Java implementers to optimize the Stream API.

</details>


### [3] [Misleading Microbenchmarks on the Java Virtual Machines](https://arxiv.org/abs/2605.23570)
*Filippo Schiavio,Lubomír Bulej,Walter Binder*

Main category: cs.PL

TL;DR: 微基准测试在JVM上因无法模拟真实应用中的性能分析导向优化（profile-driven optimizations）而可能产生误导性结果，本文揭示了这一根本问题并提出了改进建议。


<details>
  <summary>Details</summary>
Motivation: 开发者常使用微基准测试（如JMH）来选择最优实现，但微基准测试在JVM等具有分层动态编译的托管运行时上，由于收集到不现实的性能分析数据（profiles），导致编译器做出激进而错误的优化，使得测试结果无法反映真实应用场景。

Method: 通过实验展示在遵循现有JMH指南的条件下，微基准测试因诱导JVM收集不真实的profile（如分支概率、接收者类型等）而产生误导性结果；并在此基础上扩展现有指南，提出使微基准测试结果更具代表性和可迁移性的具体措施。

Result: 证实了即便遵循现有微基准测试最佳实践，由于profile驱动编译的特性，微基准测试的隔离执行环境仍会导致与真实应用严重偏差的性能结果。

Conclusion: 现有微基准测试指南不足以解决JVM上profile驱动编译带来的上下文依赖问题，需要额外的措施来使微基准测试收集到更具代表性的profile，从而提高结果的可信度。

Abstract: Developers often use microbenchmarks to choose the most performant implementation of a method or a class. On the Java Virtual Machine (JVM), this is commonly done using the Java Microbenchmark Harness (JMH) which addresses common pitfalls of measuring code performance on the JVM. However, even using JMH guidelines cannot overcome the fundamental issue of context.
  Microbenchmarks inherently execute code in isolation, without interference from other application code competing for CPU resources, such as cache or branch-predictor capacity. On managed runtimes with tiered dynamic compilation, such as the JVM, the speculative, profile-driven nature of compilation decisions means that code performance is highly dependent on profiles collected during early execution. Because profiles usually include also branch probabilities and receiver types (besides code hotness metrics), a badly designed microbenchmark may cause the JVM to collect an unrealistic profile, resulting in aggressive, yet misleading, optimizations, that would not occur in a real application.
  In this paper, we demonstrate how using microbenchmarks under conditions that induce the JVM to collect unrealistic profiles yields misleading results despite following existing guidelines. We also extend these guidelines by suggesting actions to make the microbenchmark results more representative.

</details>
