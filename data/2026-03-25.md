### [1] [Let Functions Speak: Lightweight Parametric Polymorphism via Domain and Range Types](https://arxiv.org/abs/2603.23360)
*Siyuan He,Songlin Jia,Tiark Rompf*

Main category: cs.PL

TL;DR: F<:DR 演算引入域和值域投影类型 Dom(T) 和 Range(T)，用于类型化任意类型 T 的函数应用，解决 TypeScript 中依赖 any 类型的装饰器类型安全问题。


<details>
  <summary>Details</summary>
Motivation: TypeScript 中使用 Parameters<T> 和 ReturnType<T> 类型化函数装饰器时，依赖不安全的 any 类型边界，削弱了静态类型保证。需要一种类型系统来安全地处理抽象函数类型的应用。

Method: 提出 F<:DR 演算，在 System F<: 基础上添加域投影类型 Dom(T) 和值域投影类型 Range(T)。这些投影类型允许通过抽象函数类型进行类型化应用：Dom(T) 类型的参数证明可调用性，结果类型化为 Range(T)。使用 Rocq 进行机械化实现，并通过带路径选择的逻辑关系证明语义类型安全性。

Result: F<:DR 演算成功类型化了抽象函数应用，同时保持了标准基于箭头的应用规则（通过子类型化）。投影解释延迟到函数结构解析时，该技术还可扩展到其他投影类型（如原始对类型）。

Conclusion: 域和值域投影类型提供了一种类型化抽象函数应用的安全方法，解决了 TypeScript 装饰器模式中的类型安全问题，同时保持了与现有类型系统的兼容性。

Abstract: Dynamic languages such as Python and JavaScript widely use function decorators to extend behavior. In TypeScript, a common way to type such patterns uses Parameters<T> and ReturnType<T>. In practice, this idiom relies on a function-type bound for T that is expressed using the unsafe type any, which weakens static guarantees. At the core is a standard typing principle: application is justified only when the callee is exposed as an arrow type.
  We present F<:DR, a calculus that adds domain and range projection types, Dom(T) and Range(T), for arbitrary types T. These projections permit typing applications through abstract function types: an argument of type Dom(T) witnesses callability, and the result is typed as Range(T). This design complements, rather than replaces, standard arrow-based application, which remains admissible via subtyping in System F<:.
  We mechanize F<:DR in Rocq and prove semantic type soundness using logical relations with path selection, which delays projection interpretation until function structure is resolved. The same technique extends to additional projection types, illustrated for primitive pairs, i.e., product types.
