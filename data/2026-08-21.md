### [1] [Program Analysis for Adaptive Data Analysis](https://arxiv.org/abs/2608.19575)
*Jiawen Liu,Weihao Qu,Marco Gaboardi,Deepak Garg,Jonathan Ullman*

Main category: cs.PL

TL;DR: 本文提出了一种用于自适应数据分析的程序分析方法，将自适应性形式化为程序的定量属性，通过加权依赖图和路径搜索策略来上界近似自适应性，帮助识别应使用哪种技术来控制泛化误差。


<details>
  <summary>Details</summary>
Motivation: 自适应数据分析中，多个查询的链式选择会导致泛化误差在查询链中传播累积，使得单一查询的统计技术不足以保证组合分析的整体泛化误差。虽然已有多种技术可以保证组合分析的边界，但如何根据自适应数据分析的查询结构选择合适的技术仍是一个问题。

Method: 将自适应数据分析建模为while类程序；形式化自适应性为程序的定量属性；设计程序分析，将数据分析表示为加权依赖图，其中权重上界变量可达次数；使用路径搜索策略来上界近似自适应性；实现该程序分析并使用具体的数据分析案例进行验证。

Result: 程序分析能够分析多个具有不同自适应结构的具体数据分析实例，成功识别并近似它们的自适应性程度。

Conclusion: 提出的程序分析方法可以有效地形式化和近似量化自适应数据分析中的自适应性，为选择合适的技术来控制泛化误差提供了自动化工具支持。

Abstract: Data analyses are usually designed to identify some property of the population from which the data are drawn, generalizing beyond the specific data sample. For this reason, data analyses are often designed to produce a low generalization error, so that the result of an analysis on sample data does not differ too much from the result one would achieve over the entire population.
  An adaptive data analysis can be seen as a process composed of multiple queries interrogating some data, where the choice of which query to run next may rely on the results of previous queries. The generalization error of each individual query can be controlled using well-established statistical techniques. However, when queries are arbitrarily composed, errors can propagate through the chain of queries and lead to high generalization error. To address this issue, several techniques guarantee bounds not only on single queries but also on composed analyses. The choice of technique often depends on the chain of queries that an adaptive data analysis can generate.
  In this work, we consider adaptive data analyses implemented as while-like programs and design a program analysis to help identify which technique to use to control their generalization errors. More specifically, we formalize the intuitive notion of adaptivity as a quantitative property of programs. Based on this definition, we design a program analysis for soundly approximating this quantity. The analysis represents the data analysis as a weighted dependency graph, where weights upper-bound how often variables can be reached, and uses a path-search strategy to upper-bound adaptivity. We implement our program analysis and show that it can analyze several concrete data analyses with different adaptivity structures.

### [2] [Escaping the Quicksand: A Call to Arms](https://arxiv.org/abs/2608.19674)
*Peter Sewell,Jean Pichon-Pharabod*

Main category: cs.PL

TL;DR: 本文主张采用"测试+规约+证明"的灵活组合方法（而非单纯依赖测试或纯数学证明）来改善软件工程实践，通过可执行的部分规约和语义基础设施，为AI和人类开发者建立更有效的反馈循环，从而减少技术债务和系统风险。


<details>
  <summary>Details</summary>
Motivation: 75年来基于测试-调试的软件开发模式虽然支撑了工业繁荣，但反馈循环昂贵且低效，累积的技术债务带来巨大的商业和社会风险。AI赋能的工程化在降低成本的同时也加速了技术债务累积和漏洞检测的自动化需求。纯数学正确性证明虽能覆盖所有情况，但应用困难且存在技术及文化层面的脱节。

Method: 提出务实的渐进式方法：(1) 最低层面——将与代码共同演化的可执行部分规约作为测试预言器（test oracle），与散文描述、代码和测试协同开发；(2) 更高层面——使用支持测试、基于属性的测试（property-based testing）、符号执行和证明全谱系的规约，形成从廉价的测试到昂贵的证明之间的多层级交织反馈循环；(3) 关键是建设"语义基础设施"——为主流编程语言和其他抽象构建规约与工具链。

Result: 论文指出技术上可行的路径已有，即通过部分规约强化测试区分度、通过全谱系规约工具实现从测试到证明的连续反馈。但真正的实用性依赖尚未就位的语义基础设施，需要社区共同建设。

Conclusion: 呼吁社区采取行动（"call to arms"），创建并部署语义基础设施，使规约驱动工程在主流编程语言中真正实用化，从而为AI和人类开发建立更坚实的软件工程基础，走向更稳固的未来。

Abstract: Computing has been an astonishing success - but the accumulated technical debt exposes us all to huge costs in business and societal risk. For 75 years, we've built systems to prose specifications with test-and-debug development. That works well enough for industry to thrive, but it's an expensive and ineffective feedback loop, and leaves everyone relying on shaky foundations. Now, AI-enabled engineering is amplifying the success by reducing coding costs, but also amplifies the risks, by rapidly increasing technical debt, and by automating detection of the vulnerabilities therein.
  How can we do better? Research has long pursued mathematical proof of correctness, which, unlike testing, can cover all cases. This too has advanced massively, but it remains hard to apply, both technically and because of a deep-seated cultural disconnect.
  Instead, we argue for a pragmatic approach to flexible combinations of testing, *specification*, and proof, that provides more effective feedback loops for both AI and human development.
  Most simply, one can incrementally co-develop executable-as-test-oracle partial specifications alongside conventional prose descriptions, code, and tests. This clarifies design and makes testing much more discriminating. Developers can and should do it today.
  Or, even better, one can use specifications that support the full gamut of testing, property-based testing, symbolic execution, and proof. This enables a range of intertwined feedback loops, again both for AI and humans, from cheap testing to more expensive proof. However, making it really practical needs *semantics infrastructure*: specifications and tooling for the main programming languages and other abstractions, which we now more-or-less know how to build, but which is not yet in place. We call the community to arms to create and deploy it - to enable a future built on firmer ground.

</details>


### [3] [Hippogriff: a semantic approach to uniting core and modules](https://arxiv.org/abs/2608.19728)
*Owen Lynch,Sam Staton*

Main category: cs.PL

TL;DR: 本文介绍Hippogriff，一种统一了核心层与模块层语法的依赖类型语言，通过小类型宇宙支持模块化特性，同时在不导致类型检查非终止的情况下支持一般递归。论文前半部分描述Hippogriff及其实现，后半部分使用扩展的第二序广义代数理论建立范畴语义，引入综合相位区分来证明值层一般递归的合理性，并在依赖类型理论与分裂上下文类型理论（如System F）之间建立数学联系。


<details>
  <summary>Details</summary>
Motivation: 现有的依赖类型语言中，模块系统与核心语言语法往往分离，增加了语言复杂度和使用难度。同时，在依赖类型系统中支持一般递归通常会使类型检查失去终止性保证，这在理论与实践上都构成挑战。作者希望统一模块层与核心层语法，并在保持类型检查终止的同时支持值层的一般递归，并通过范畴语义为其提供理论基础。

Method: 作者设计了Hippogriff语言，其类型理论是依赖类型的，通过宇宙（universe of small types）来实现模块化特性，从而统一核心层与模块层的语法。在语义方面，作者扩展了第二序广义代数理论框架，引入综合相位区分（synthetic phase distinction），以此在依赖类型理论和分裂上下文类型理论（如System F）之间建立数学联系，进而证明支持值层一般递归的合理性。论文还提供Haskell实现及完整类型理论的附录。

Result: 成功设计并实现了Hippogriff语言，实现了核心层与模块层语法的统一；通过扩展的第二序广义代数理论建立了范畴语义，证明了一般递归在值层的使用不会导致类型检查终止性丧失；在依赖类型理论与分裂上下文类型理论之间建立了数学联系，并以Haskell实现作为补充验证。

Conclusion: Hippogriff证明了可以通过统一核心层与模块层语法来简化依赖类型语言的设计，同时通过引入综合相位区分的语义框架，可以在理论上证明依赖类型系统中支持一般递归的合理性。这一工作为模块系统与依赖类型理论的统一提供了新的语义基础和实现路径。

Abstract: In this paper we introduce Hippogriff, a language with a module system that unifies syntax between the core level and the module level. Hippogriff's type theory is dependent, with modularity features enabled via a universe of small types, but Hippogriff still supports general recursion without making typechecking nonterminating. This paper contains two halves. In the first half, we describe Hippogriff and its implementation. In the second half, we build categorical semantics for our use of dependent types that justify the use of general recursion at the value level. Specifically, we use an extension of the second-order generalized algebraic theory framework to include a synthetic phase distinction, and this allows us to make a mathematical connection between dependent type theories and split-context type theories (like System F). Included as supplements are a Haskell implementation of Hippogriff and an appendix describing the full type theory of Hippogriff using a second-order generalized algebraic theory with phase distinction.

</details>


### [4] [Formal Performance and Compile Time Guarantees for Compiler Optimization Heuristics](https://arxiv.org/abs/2608.20137)
*Nikil V. Shyamsunder*

Main category: cs.PL

TL;DR: 本文提出对编译器pass的性能和编译时间属性进行形式化验证，并以内联展开为概念验证，在Rocq证明助手中机械化实现了基于指令缓存性能成本模型的内联转换，证明了语义保持、单调改进性、收敛时间界限以及中间和最终解的性能界限。


<details>
  <summary>Details</summary>
Motivation: 现代优化编译器依赖启发式搜索算法处理NP难优化问题，可能导致生成的代码性能差、编译时间长或不可预测，这些问题被用户视为bug，但已验证编译器通常只关注语义保持而不对性能和编译时间进行推理。

Method: 以Rocq证明助手为平台，通过成本模型估算指令缓存性能来形式化内联展开，同时证明内联转换的语义保持性质，并验证算法的单调改进、收敛时间界限以及中间和最终解的性能界限。

Result: 作为概念验证，成功在Rocq中机械化内联展开，同时证明了语义保持、算法单调改进性、收敛时间上界以及中间和最终解的缓存性能界限。

Conclusion: 该工作表明编译器pass的性能属性和编译时间属性可以通过形式化方法进行验证，超越了传统已验证编译器仅保证语义保持的范畴，为编译器优化过程的可靠性和可预测性提供了新的验证方向。

Abstract: Modern optimizing compilers rely on heuristic search algorithms for NP-hard optimization problems, which can result in poor generated-code performance and long or unpredictable compile times. These are considered bugs by users, but verified compilers rarely reason beyond semantic preservation. We propose verifying performance and compile time properties of compiler passes. As a proof-of-concept, we formulate inline expansion using a cost model estimating instruction-cache performance. We mechanize this in Rocq, prove semantic preservation of the inlining transformation, and verify the algorithm's monotone improvement, convergence-time bound, and performance bounds for intermediate and final solutions.

</details>
