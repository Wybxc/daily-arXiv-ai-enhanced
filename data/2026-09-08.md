### [1] [Corten - Foundational Verification of Rust Programs](https://arxiv.org/abs/2609.04372)
*František Farka,Carmine Abate,Sven Linker,Sebastian Ertel*

Main category: cs.PL

TL;DR: Corten是一个基于Iris分离逻辑、构建于Rocq定理证明器中的Rust程序基础验证框架。它首次在证明助手中提供表面级Rust（通过THIR深层嵌入）的机械化语义并附带程序逻辑，直接扎根于Rust Reference。通过在THIR层操作，证明目标可美化为表面Rust代码；程序逻辑采用反函数化续延栈保持证明目标一阶且紧凑。其健全性以构造为单位渐进地针对interaction-trees指称语义建立。合成测试套件显示相比原始语义证明缩减2-4倍证明规模，并在buddy分配器案例研究中验证了内存安全。


<details>
  <summary>Details</summary>
Motivation: 在Rust程序的正式验证中，现有方法要么基于内部编译器中间表示导致验证远离源代码、难以维护，要么缺乏在证明助手中机械化的表面级语言语义与程序逻辑。作者希望建立一种直接扎根于Rust Reference、贴近源代码且具有可维护性的验证框架，弥合高级语言验证与底层系统验证之间在共享Rocq语义基础中的鸿沟。

Method: Corten将Typed High-level Intermediate Representation (THIR)深层嵌入Rocq证明器，基于Iris分离逻辑构建框架。其核心包括：(1) 将Rust动态语义形式化为最弱前置条件谓词变换子演算；(2) 开发包含反函数化续延栈的程序逻辑，使证明目标保持一阶且紧凑；(3) 构建语法导向的证明自动化层；(4) 以构造为单位渐进地建立相对于interaction-trees指称语义的健全性。THIR AST可美化打印回表面Rust，使验证与源代码保持接近。

Result: 合成测试套件表明Corten相比原始语义证明可将证明规模缩减2至4倍。在buddy分配器案例研究中，成功验证了内存分配与释放函数的内存安全，展示了框架在实际系统代码上的应用能力，并为跨越软硬件边界的端到端验证奠定基础。

Conclusion: Corten证明了在共享语义基础上进行贴近源代码的Rust程序验证是可行的，它同时提供了贴近源代码的表层语义（THIR层面）和高效的程序逻辑（通过反函数化续延栈与证明自动化），并为未来在统一Rocq语义基础中实现跨软硬件边界的端到端验证铺平了道路。

Abstract: We present Corten, a foundational verification framework for Rust programs in the Rocq theorem prover, built on the Iris separation logic framework. Corten provides the first semantics of surface-level Rust mechanized in a proof assistant with an attached program logic, directly grounded in the Rust Reference: it deeply embeds the Typed High-level Intermediate Representation (THIR) into Rocq and formalises Rust's dynamic semantics as a weakest-precondition predicate transformer calculus. By operating at THIR rather than on internal compiler representations, Corten proof goals display the THIR AST, which pretty-prints to surface Rust, keeping verification close to the source code and facilitating maintainability as code evolves. Atop this semantics, Corten develops a program logic and a syntax-directed proof automation layer; the program logic includes defunctionalized continuation stacks that keep proof goals first-order and compact. Soundness is established incrementally, construct by construct, against an interaction-trees denotation. A synthetic test suite demonstrates a two-to-four times reduction in proof size compared to raw semantic proofs. We further showcase Corten on a buddy allocator case study, verifying memory safety of the allocation and deallocation functions, laying the groundwork for end-to-end verification in a shared Rocq semantic foundation spanning hardware-software boundaries.

### [2] [JLIR: A Julia-Native MLIR-Inspired Intermediate Representation with Automatic JACC Kernel Extraction](https://arxiv.org/abs/2609.04585)
*Narasinga Rao Miniskar,Seyong Lee,Keita Teranishi,Jeffrey S Vetter*

Main category: cs.PL

TL;DR: 本文介绍了JLIR，一个Julia原生的中间表示框架，旨在将MLIR风格的多级、方言导向编译优势引入Julia生态系统，同时保持作为普通Julia代码的可使用性，克服MLIR对动态高级语言（如Julia）在类型系统和抽象层次上的不匹配问题。


<details>
  <summary>Details</summary>
Motivation: MLIR为领域特定计算提供了可复用的编译器基础设施，但其强编译期类型要求和低层C++扩展模型与Julia这类高水平动态专门化语言不匹配，使得非编译器或科学计算用户难以引入新的编程抽象和表达算法实现。

Method: JLIR采用Julia原生方式实现多级、方言导向的中间表示框架：在低层降低之前表示Julia程序，通过Julia语言机制支持可扩展操作和变换pass，允许部分类型化程序在具体类型确定前保持可变换性，并以轻量机制支持添加新领域操作而无需修改核心系统。框架内置算术、控制流、函数、结构化循环和内存操作等方言。

Result: 论文将JLIR应用于自动Julia for Accelerators (JACC)内核生成，展示了其在实际场景中的能力和效果。

Conclusion: JLIR表明可以通过Julia自身的语言机制实现MLIR风格的编译框架优势，使Julia生态系统中的库接口（如线性代数、网格处理、偏微分方程等领域）能够进入编译器优化路径，同时降低用户使用门槛。

Abstract: The Multi-Level Intermediate Representation (MLIR) has made reusable compiler infrastructure practical for domain-specific computation. However, MLIR's strong compile-time type requirements and low-level (C++) extension model can be a poor match for high-level, dynamically specialized languages such as Julia. MLIR has several drawbacks for dynamic programming languages in terms of the type system and level of abstraction. It is thus extremely challenging for non-compiler or scientific computing users to introduce new programming abstractions and express algorithm implementations in a form that remains both natural and optimizable. As a result, library interfaces for linear algebra, mesh processing, partial differential equations, and related domains often sit outside the compiler optimization path. We present JLIR (Julia-native Level Intermediate Representation), a Julia-native intermediate representation framework that brings the main benefits of MLIR-style multi-level, dialect-oriented compilation into the Julia ecosystem while remaining usable as ordinary Julia code. JLIR represents Julia programs before low-level lowering, supports extensible operations and transformation passes through Julia's language mechanisms, and allows partially typed programs to remain transformable until concrete types are known. The framework includes built-in dialects for arithmetic, control flow, functions, structured loops, and memory operations, and it also includes a lightweight mechanism for adding new domain operations without modifying the core system. To demonstrate JLIR's capabilities, we applied it to automatic Julia for Accelerators (JACC) kernel generation.

### [3] [CPL: A Compact C-like Systems Language with Explicit Low-Level Control](https://arxiv.org/abs/2609.04904)
*Nikolay Fot,Alexander Vinarsky*

Main category: cs.PL

TL;DR: 本文介绍了Cordell编程语言（CPL），一种紧凑的类C系统语言，保留C对内存、布局和机器接口的直接访问能力，同时实验性地引入更精简的语法和现代语言的便利特性，并评估其编译器在x86_64和i386上生成的代码与GCC、Clang等生产级编译器及TinyC、SmallerC等小型编译器相当。


<details>
  <summary>Details</summary>
Motivation: 探讨类C语言相较于现代编程范式在编译器实验中是否更方便使用，并验证一个精简语法设计的类C语言编译器能否生成与主流编译器竞争的高质量代码。

Method: 设计了包含基础值类型、指针、数组、带方法的容器、联合体、泛型函数、重载、入口点与段控制、系统调用和内联汇编等特性的CPL语言，但排除类、内建方法、标准库和内存保护等高级构造；实现了编译器流水线、目标后端、静态分析架构和面向操作系统的用例，并通过x86_64和i386可复现微基准测试与GCC、Clang、TinyC、SmallerC等编译器进行对比评估。

Result: 实验结果表明CPL编译器能够生成与生产级编译器GCC和Clang，以及小型编译器TinyC和SmallerC相当的代码质量。

Conclusion: 精简设计的类C系统语言在保持低层访问能力的同时，可以通过实验性语法带来便利性，且其编译器生成的代码质量足以与现有主流及小型编译器相媲美。

Abstract: This paper presents Cordell Programming Language (CPL), a compact C-like systems language that retains C's direct access to memory, layout, and machine interfaces while experimenting with a smaller grammar and selected conveniences from newer languages. Also this paper studies whether C-like are more convenient to use for compiler experiments than modern approaches and paradigms. While the language and compiler provide primitive values, pointers, arrays, containers with methods, unions, generic functions, overloads, entry-point and section control, system calls, and inline assembly, they do not provide high-level constructs such as classes, built-in methods, a standard library, or memory protection. The article describes the language design, compiler pipeline, target backends, static-analysis architecture, and OS-facing use cases, then evaluates the prototype backend with reproducible x86_64 and i386 microbenchmarks against C compiler baselines. The obtained results suggest that the compiler can produce code comparable to that produced by production compilers such as GCC and Clang, as well as by small compilers such as TinyC and SmallerC.

### [4] [Augur: Predicting View Serializability Violations in Relational Data Store Applications](https://arxiv.org/abs/2609.05288)
*Chujun Geng,Noah Charlton,Spyros Blanas,Michael D. Bond,Yang Wang*

Main category: cs.PL

TL;DR: 本文提出了Augur，这是首个支持复杂关系查询（SQL）且仅报告违反视图可串行化（View Serializability）执行的动态预测程序分析工具，用于检测数据存储应用中的不可串行化执行。


<details>
  <summary>Details</summary>
Motivation: 数据存储应用广泛使用弱隔离来获得可扩展性能，但会导致零星的不串行化执行，造成错误或失败。现有基于动态预测分析的方法无法处理具有复杂谓词的关系型（SQL）查询，且其预测的执行并不违反视图可串行化。

Method: Augur是一种动态预测程序分析工具，支持带有复杂关系查询的数据存储应用，并仅报告违反视图可串行化（View Serializability）的执行。

Result: 评估表明，Augur能够在广泛使用的OLTP-Bench程序和电子商务应用Spree中发现可行的、不可串行化的执行。

Conclusion: Augur填补了现有动态预测分析在处理复杂SQL查询和视图可串行化判定方面的空白，能够有效地发现真实数据存储应用中违反串行化的可行执行。

Abstract: Data stores are widely used because they provide persistence, scalability, and fault tolerance with a simple interface. However, most data store applications configure the data store to use weak isolation to achieve scalable performance, resulting in sporadic unserializable executions that are incorrect or fail. Prior work uses dynamic predictive analysis to infer violations from execution traces, but it cannot handle relational (i.e., SQL) queries with complex predicates, and it predicts executions that do not violate View Serializability.
  This paper introduces Augur, the first dynamic predictive program analysis that (1) supports data store applications with complex relational queries and (2) reports only executions that violate View Serializability. The evaluation demonstrates that Augur finds feasible, unserializable executions in the widely used OLTP-Bench programs and in the widely used e-commerce application Spree.

### [5] [Design Docs Are All You Need: An AI-native Machine-Learning Performance Tool](https://arxiv.org/abs/2609.05364)
*Samuel Kushnir,Kimia Noorbakhsh,Kavya Sreedhar,Liqun Cheng,Ming Liu,Parthasarathy Ranganathan,Mohammad Alizadeh,Fred Kjolstad,Suvinay Subramanian*

Main category: cs.PL

TL;DR: 本文提出SMART，一个基于文档驱动的符号化ML系统性能建模库。其主分支几乎不含代码，而是由自然语言设计文档构成的DAG(有向无环图)；编码子代理在版本更新时仅凭文档重新生成实现，所有人类修改都以自然语言编辑文档完成。通过设计文档中的逐步工作示例作为上下文演示，以及一个最小化的递归运算符IR，重新生成的实现能精确复现手工审计的参考模型。


<details>
  <summary>Details</summary>
Motivation: 机器学习性能建模领域对长期维护的软件极不友好：现有抽象中的假设会随模型和系统的演进而失效，迫使性能建模框架不断地被重构。与此同时，AI编码代理速度足够快、能力足够强，从头重新生成整个代码库比逐步修补技术债更经济。

Method: SMART的核心设计包括两个关键成分：(1) 一种设计文档风格，基于逐步工作示例，这些示例作为生成代理的上下文内演示(in-context demonstrations)；(2) 一个最小化、递归定义的运算符中间表示(IR)，包含使用SymPy的符号化成本表达式，提供两种模式——快速分析卷加(roll-up)模式用于大规模扫描，以及慢速模调度(modulo-scheduling)模式用于细粒度调度研究。代码库本身是一个自包含自然语言设计文档的DAG，编码子代理据此重新生成实现。

Result: 重新生成的实现能以舍入精度(round-off precision)复现手工审计的参考模型，包括在TPU pod切片上服务DeepSeek-V3的场景。这表明基于文档而非代码的方法在实际复杂ML系统性能建模中达到精确可验证的准确性。

Conclusion: 本文结论认为设计文档(而非代码)可以作为ML系统协同设计工具中持久、耐用的工件(artifact)。文档驱动的自动再生成范式能应对ML领域快速演进带来的技术债问题，实现自文档化(self-documenting)的代码库架构。

Abstract: Machine-learning performance modeling is a uniquely hostile terrain for long-lived software: the assumptions baked into today's abstractions are invalidated by tomorrow's models and systems, forcing perpetual refactoring of performance-modeling frameworks. Meanwhile, AI coding agents have become fast and capable enough that regenerating an entire library is cheaper than paying down the tech debt of incrementally patching it. We describe SMART, a rigorous symbolic performance-modeling library for ML systems whose main branch contains almost no code: the repository is a DAG of self-contained natural-language design docs, coding sub-agents regenerate the implementation from only the docs on new version updates, and every human change is a natural-language edit to a doc--self-documenting by construction. Two ingredients make regeneration reliable: (i) a design-doc style built around step-by-step worked examples that act as in-context demonstrations for the generating agents, and (ii) a minimal, recursively defined operator IR with symbolic (SymPy) cost expressions, a fast analytical roll-up mode for large sweeps, and a slow modulo-scheduling mode for fine-grained schedule studies. Regenerated implementations reproduce hand-audited reference models--including DeepSeek-V3 serving on a TPU pod slice--to round-off precision, suggesting that design docs--not code--can be the durable artifact for ML-systems co-design tools.

</details>
