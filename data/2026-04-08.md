*Hubert Garavel*

TL;DR: LNT语言通过引入编程风格特性改进并发系统建模，以Algorand共识协议为例展示代码精简和可读性提升


<details>
  <summary>Details</summary>
Motivation: LNT语言作为现代并发系统形式化描述语言，虽然克服了传统进程演算的局限性，但如何充分利用其特性（如命令式编程风格、变量直接赋值、对称顺序组合和显式循环操作符）来获得更简洁、可读性更强的模型仍需要研究

Method: 通过精心选择的变换技术，以Algorand区块链共识协议为运行示例，展示如何优化LNT模型。采用视觉检查、等价性检查和模型检查等多种验证方法表达和验证形式化模型的各种属性

Abstract: LNT is a modern language for the formal description of concurrent systems. It generalizes traditional process calculi and overcomes their known limitations by incorporating features such as an imperative programming style with direct assignments to variables, symmetric sequential composition, and explicit loop operators. The present article examines how these features can be taken advantage of to obtain LNT models as concise and readable as possible. The study is illustrated with a running example, the consensus protocol of the Algorand blockchain, a formal model of which was recently developed at the University of Urbino. It is shown that, using well-chosen transformations, the number of lines of LNT code can be divided by three, while improving readability. Also, various properties of the formal model are expressed and verified using visual checking, equivalence checking, and model checking.

### [2] [AutoLALA: Automatic Loop Algebraic Locality Analysis for AI and HPC Kernels](https://arxiv.org/abs/2604.05066)
*Yifan Zhu,Yekai Pan,Yanghui Wu,Chen Ding*

Main category: cs.PL

TL;DR: AutoLALA是一个开源工具，用于分析仿射循环程序的数据局部性，通过符号化方法计算重用距离和数据移动复杂度，支持多种高性能计算和AI工作负载。


<details>
  <summary>Details</summary>
Motivation: 现代计算系统中数据移动是主要瓶颈，特别是在高性能计算和AI工作负载中（如矩阵乘法、张量收缩、模板计算等），数据在内存层次结构中移动的成本常常超过算术运算成本。

Method: AutoLALA接受用小型领域特定语言编写的程序，将其转换为多面体集合和映射，通过仿射变换构建时间戳空间和访问映射，使用Barvinok计数操作推导符号化的重用间隔和重用距离分布。

Result: 开发了一个模块化的Rust库，提供命令行接口和交互式Web playground，支持LaTeX渲染输出公式，能够处理任意仿射循环嵌套，覆盖张量收缩、einsum表达式、模板计算等各类工作负载。

Conclusion: AutoLALA实现了完全符号化的局部性分析，避免了堆栈模拟和Denning的递归工作集公式，为仿射循环程序的数据局部性分析提供了有效的工具支持。

Abstract: Data movement is the primary bottleneck in modern computing systems. For loop-based programs common in high-performance computing (HPC) and AI workloads, including matrix multiplication, tensor contraction, stencil computation, and einsum operations, the cost of moving data through the memory hierarchy often exceeds the cost of arithmetic.
  This paper presents AutoLALA, an open-source tool that analyzes data locality in affine loop programs. The tool accepts programs written in a small domain-specific language (DSL), lowers them to polyhedral sets and maps, and produces closed-form symbolic formulas for reuse distance and data movement complexity. AutoLALA implements the fully symbolic locality analysis of Zhu et al. together with the data movement distance (DMD) framework of Smith et al. In particular, it computes reuse distance as the image of the access space under the access map, avoiding both stack simulation and Denning's recursive working-set formulation.
  We describe the DSL syntax and its formal semantics, the polyhedral lowering pipeline that constructs timestamp spaces and access maps via affine transformations, and the sequence of Barvinok counting operations used to derive symbolic reuse-interval and reuse-distance distributions. The system is implemented in Rust as a modular library spanning three crates, with safe bindings to the Barvinok library.
  We provide both a command-line interface and an interactive web playground with LaTeX rendering of the output formulas. The tool handles arbitrary affine loop nests, covering workloads such as tensor contractions, einsum expressions, stencil computations, and general polyhedral programs.

### [3] [EffiPair: Improving the Efficiency of LLM-generated Code with Relative Contrastive Feedback](https://arxiv.org/abs/2604.05137)
*Samira Hajizadeh,Suman Jana*

Main category: cs.PL

TL;DR: EffiPair：基于相对对比反馈的代码效率优化框架，无需模型微调，通过对比相似程序的结构差异来指导生成更高效的代码。


<details>
  <summary>Details</summary>
Motivation: 现有方法依赖单个程序的绝对执行反馈（如运行时分析），成本高且指导性弱，需要更有效的效率优化机制。

Method: 提出相对对比反馈(RCF)机制，比较同一任务的两个结构相似程序，突出效率差异；构建EffiPair框架，在推理时生成多个候选方案，识别效率差距大的程序对，总结执行差异为轻量反馈，指导生成更高效解决方案。

Result: 在代码效率基准测试中，EffiPair持续提升效率同时保持正确性。使用DeepSeek-Chat V3.2时，相比无性能反馈的生成，实现最高1.5倍加速，相比先前工作减少90%以上token使用。

Conclusion: 相对对比反馈比绝对反馈提供更直接指导，减少分析和提示开销，在推理时有效提升LLM生成代码的效率。

Abstract: Large language models (LLMs) often generate code that is functionally correct but inefficient in runtime and memory. Prior approaches to improving code efficiency typically rely on absolute execution feedback, such as profiling a single program's runtime or memory usage, which is costly and provides weak guidance for refinement. We propose Relative Contrastive Feedback (RCF), an inference-time feedback mechanism that requires no model fine-tuning or parameter updates. RCF compares two structurally similar programs for the same task and highlights the differences associated with better efficiency. Building on this idea, we introduce EffiPair, an inference-time iterative refinement framework that operates entirely at test time by generating multiple candidate solutions, identifying informative program pairs with large efficiency gaps, summarizing their execution differences into lightweight feedback, and using this signal to produce more efficient solutions. By replacing isolated scalar feedback with pairwise contrastive comparisons, EffiPair provides more direct guidance while reducing profiling and prompting overhead. Experiments on code-efficiency benchmarks show that EffiPair consistently improves efficiency while preserving correctness. For instance, with DeepSeek-Chat V3.2, EffiPair achieves up to 1.5x speedup over generation without performance feedback, while reducing token usage by more than 90% compared to prior work.

### [4] [A Gradual Probabilistic Lambda Calculus](https://arxiv.org/abs/2604.05246)
*Wenjia Ye,Matías Toro,Federico Olmedo*

Main category: cs.PL

TL;DR: 该论文提出了GPLC，一个渐进的源概率λ演算，将渐进类型引入概率编程语言，支持静态和动态检查之间的平滑过渡。


<details>
  <summary>Details</summary>
Motivation: 概率编程语言在机器学习和差分隐私等领域应用广泛，通常使用类型系统进行静态检查，但这可能繁琐或过于保守。渐进类型支持静态和动态检查的平滑过渡，但尚未在概率语言中探索其优势。

Method: 提出并形式化GPLC，包含二元概率选择算子，允许程序员逐步引入/移除静态类型和概率注释。静态语义基于概率耦合概念，动态语义通过精化到目标语言TPLC实现，后者采用基于分布的语义将程序解释为最终值的概率分布。

Result: 建立了TPLC（因此也包括GPLC）的类型安全性，并满足渐进语言的细化标准：是静态变体的保守扩展，并满足渐进保证，相对于类型精度行为平滑。

Conclusion: 该工作首次将渐进类型引入概率编程语言，通过GPLC展示了如何在概率语言中实现静态和动态检查的平滑过渡，为概率编程提供了更灵活的类型系统。

Abstract: Probabilistic programming languages have recently gained a lot of attention, in particular due to their applications in domains such as machine learning and differential privacy. To establish invariants of interest, many such languages include some form of static checking in the form of type systems. However, adopting such a type discipline can be cumbersome or overly conservative.
  Gradual typing addresses this problem by supporting a smooth transition between static and dynamic checking, and has been successfully applied for languages with different constructs and type abstractions. Nevertheless, its benefits have never been explored in the context of probabilistic languages.
  In this work, we present and formalize GPLC, a gradual source probabilistic lambda calculus. GPLC includes a binary probabilistic choice operator and allows programmers to gradually introduce/remove static type -- and probability -- annotations. The static semantics of GPLC heavily relies on the notion of probabilistic couplings, as required for defining several relations, such as consistency, precision, and consistent transitivity. The dynamic semantics of GPLC is given via elaboration to the target language TPLC, which features a distribution-based semantics interpreting programs as probability distributions over final values. Regarding the language metatheory, we establish that TPLC -- and therefore also GPLC -- is type safe and satisfies two of the so-called refined criteria for gradual languages, namely, that it is a conservative extension of a fully static variant and that it satisfies the gradual guarantee, behaving smoothly with respect to type precision.
