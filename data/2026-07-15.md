### [1] [Bidirectional Type Slicing](https://arxiv.org/abs/2607.12197)
*Max Carroll,Anil Madhavapeddy,Cyrus Omar*

Main category: cs.PL

TL;DR: 本文提出类型切片（type slicing）理论：程序员选择表达式中的某个项，查询其类型信息中的任意部分，系统返回足以复现该查询类型的程序切片。该理论适用于双向类型系统，支持合成切片（解释项合成的类型）和分析切片（解释上下文期望的类型），并向下兼容静态渐近性。核心贡献包括：最小切片存在性证明、查询精细化与最小切片单调收缩关系、精确与近似切片计算方法，以及与错误标记理论结合后对任意错误程序的扩展。理论在Agda中机械化实现，线性时间近似版本部署于Hazel编程环境。


<details>
  <summary>Details</summary>
Motivation: 现有开发工具能报告表达式的类型（what），但无法解释类型为何如此（why）。为弥补这一缺失，本文提出类型切片理论，帮助程序员理解类型推导的根源。

Method: 基于双向类型系统，结合Hazelnut和标记lambda演算，在包含洞、积、和与显式多态的核心演算上建立理论。利用精度偏序和向下静态渐近性保证切片正确性，通过错误标记理论扩展至任意错误程序。

Result: 证明了每个查询存在最小切片；查询精细化导致最小切片单调收缩；给出了精确与近似的切片计算方法；与错误标记理论融合后适用于任意类型正确/错误/不完整程序。

Conclusion: 类型切片为理解类型推导原因提供了统一框架，兼顾理论完整性与实际可用性（线性时间近似），已在实际编程环境Hazel中实现。

Abstract: Development tools report what type an expression has, but not why it has that type. This paper develops a theory of type slicing: a programmer selects a term, queries any part of its type information, and receives a program slice that is sufficient to reproduce the queried type. We formulate type slicing for bidirectional type systems, where synthesis slices explain the type a term synthesises and analysis slices explain the type expected by its surrounding context. The theory applies to any bidirectional system equipped with precision orders on types and terms satisfying a downwards static graduality property. We develop the metatheory over a core calculus with holes, products, sums, and explicit polymorphism, based on the Hazelnut and marked lambda calculi. We prove that every query has a minimal slice and that refining a query monotonically shrinks its minimal slices. We then show how to calculate these slices both exactly and approximately. Finally, integrating type slicing with error marking theory extends these results to arbitrary ill-typed programs, so a single mechanism explains both types and type errors in complete, incomplete, and erroneous code. The metatheory is mechanised in Agda, and a linear-time approximation of type slicing is implemented for the Hazel programming environment.

### [2] [Foundational Constraint Solving for Expressive Refinement Typing](https://arxiv.org/abs/2607.12226)
*Jam Kabeer Ali Khan,Petros Markopoulos,Nico Lehmann,Ranjit Jhala*

Main category: cs.PL

TL;DR: 本文提出FLEX，一个在LEAN中实现的基础约束Horn子句（CHC）求解器，通过将CHC编码为LEAN命题、实现可生成内核可验证证明的策略，以及构建端到端的基础CHC验证器，在减少可信计算基的同时，利用LEAN证明生态突破了SMT求解器的表达性限制。实验表明FLEX能自动消解FLUX基准套件中95.7%的CHC。


<details>
  <summary>Details</summary>
Motivation: 基于SMT的程序验证器面临两大问题：一是可预测验证限制了SMT可判定性的边界，导致表达性不足；二是SMT求解器作为大型未验证工具，其可靠性缺陷可能影响所有基于它构建的工具，存在信任问题。

Method: 1. 将CHC编码为LEAN命题，其中Horn变量作为存在绑定的谓词，并在LEAN中实现CHC求解器作为战术（元程序），生成内核可检查的证明；2. 在LEAN中实现两种经过验证的CHC生成器：面向命令式语言的Floyd-Hoare风格生成器和面向函数演算的基于 refinement type 的生成器，与求解战术组合形成端到端的基础CHC验证器；3. 利用LEAN的整个证明生态来证明低级Rust库的功能正确性。

Result: FLEX能自动消解FLUX基准套件中95.7%的CHC，验证了其作为可信CHC后端的可行性。通过利用LEAN生态突破了SMT的表达性限制，证明了低级Rust库的任意功能正确性属性。

Conclusion: FLEX通过将CHC求解器实现为LEAN战术，成功将可信计算基缩减到LEAN内核，同时利用LEAN的证明生态克服了SMT求解器的表达性限制，为构建可信、表达性强的程序验证工具提供了新范式。

Abstract: SMT-based program verifiers are hamstrung by two problems: expressiveness, because predictable verification restricts to the boundaries of SMT decidability, and trust, because the solver is a large, unverified artifact whose soundness bugs may quietly compromise every tool built on it. We present FLEX, a foundational Constrained Horn Clause (CHC) solver implemented in LEAN, that reduces the trusted base to the kernel alone, and allows using LEAN's entire proof ecosystem to verify low-level systems code, via three contributions. First, FLEX encodes CHCs as plain LEAN propositions where the Horn variables are existentially bound predicates, and shows how to implement CHC solvers as tactics (meta-programs) that compute kernel checkable proofs of the CHC propositions. Second, we show how to implement two verified CHC generators in LEAN: a Floyd-Hoare style generator for an imperative language, and a refinement-type-based generator for a functional calculus, which can be composed with the solving tactics to yield the first end-to-end foundational CHC-based verifiers. Finally, we show how FLEX allows us to leapfrog the expressiveness limitations of SMT by unleashing LEAN's entire ecosystem of proof machinery to prove arbitrary functional correctness properties of various low-level Rust libraries using the FLUX refinement type checker, and demonstrate the viability of FLEX as a trustworthy CHC backend, by showing it automatically discharges 95.7% of the CHCs from FLUX's benchmark suite.

</details>


### [3] [Verifying Probabilistic Programs in Rust](https://arxiv.org/abs/2607.12282)
*Alexander Y. Bai,Joseph Tassarotti*

Main category: cs.PL

TL;DR: 本文提出 Alerus，一个基于 Verus 扩展的 Rust 概率程序验证框架。它通过轻量级编码概率错误信用（Eris 逻辑中的幽灵状态）来支持随机采样算法的形式化验证，并在 Rocq 中机械化证明了其可靠性。


<details>
  <summary>Details</summary>
Motivation: 现有的概率程序验证框架局限于为验证设计的理想化语言，无法验证标准语言（如 Go、C、Rust）编写的现成概率程序。本文希望重用非概率程序验证工具（如 Verus）的已有成果，为 Rust 概率程序提供验证能力。

Method: Alerus 基于 Verus 验证工具（支持 SMT 自动化与分离逻辑推理），通过轻量级编码 Eris 程序逻辑中的概率错误信用（一种用于随机推理的幽灵状态）来扩展概率推理能力。通过使用错误信用推导适当的规约，支持验证随机抽样算法的正确性。可靠性证明通过将 VerusBelt（Verus 的逻辑关系模型）中的 Iris 标准最弱前置条件替换为 Eris 的概率最弱前置条件，并在 Rocq 中机械化完成。

Result: 验证了多个离散分布采样例程，包括离散高斯分布采样器、别名方法以及快速加载骰子滚动器（fast loaded dice roller）。

Conclusion: Alerus 成功将概率推理能力扩展到 Rust 验证工具中，实现了对现成概率程序的形式化验证，且可靠性证明已完全机械化。

Abstract: Recent work has developed many techniques for formally verifying probabilistic programs. However, existing verification frameworks for probabilistic programs are restricted to idealized languages designed for verification. As a result, they cannot be used to verify off-the-shelf probabilistic programs written in standard languages. In contrast, for non-probabilistic programs, a number of verification tools now support verifying realistic code written in widely used languages such as Go, C, and Rust. To verify probabilistic programs written in these languages, it would be useful to be able to reuse, as much as possible, the extensive development work that has gone into such tools.
  This paper presents Alerus, a framework for verifying probabilistic Rust programs. Alerus is based on Verus, a verification tool for Rust that supports SMT-based automation and separation-logic-inspired reasoning features. Alerus extends Verus with support for probabilistic reasoning while retaining these expressive features. To do so, Alerus uses a lightweight encoding of probabilistic error credits, a form of ghost state for randomized reasoning introduced in the Eris program logic. By deriving an appropriate specification using error credits, Alerus supports verifying the correctness of randomized sampling algorithms. We use this technique to verify several sampling routines for discrete distributions, including samplers for the discrete Gaussian distributions, the alias method, and the fast loaded dice roller.
  We establish the soundness of our error credit extension by adapting VerusBelt, a recently developed logical relations model of Verus that encodes its features in terms of the Iris separation logic. To do so, we replace the use of Iris's standard weakest precondition in this model with Eris's probabilistic weakest precondition instead. The resulting soundness proof is fully mechanized in Rocq.

### [4] [Mystra: Declarative Dynamic Taint Analysis via Shadow Virtual Machine](https://arxiv.org/abs/2607.12308)
*Zhuohao Zhang,Junkun Liu,Rui Yang,Yinzhi Cao,Ziyang Li*

Main category: cs.PL

TL;DR: 本文提出Shar，一种基于影子虚拟机（Shadow Virtual Machine）的动态污点分析引擎，通过声明式规范语言Mystra实现跨运行时（V8、SpiderMonkey、CPython）的高性能、高精度污点追踪，在SecBench.js上达到95.5%召回率和零误报，运行时开销仅为原生Node.js的1.85倍，比NodeMedic-FINE低22.7倍且召回率高出33.2%。


<details>
  <summary>Details</summary>
Motivation: 现有动态污点分析系统要么通过源码重写（高运行时开销），要么通过引擎原生嵌入（紧耦合、缺乏可移植性），缺乏一种独立于运行时、分离污点语义与执行机制的通用抽象。

Method: 提出影子虚拟机（Shadow VM）与宿主运行时并行执行，追踪多级污点、来源及跨调用上下文；设计声明式污点规范语言Mystra，具有形式化操作语义、对语言模型友好、内置验证器支持自动化规则合成，并首次声明式表达高阶函数污点传递；Mystra规则提前编译为二进制表示，运行时以常数时间调度。

Result: 在SecBench.js（493个CVE）上，V8实例化达95.5%召回率、零误报；运行时开销为原生Node.js的1.85倍，比NodeMedic-FINE低22.7倍，且在支持类别中召回率高33.2%。

Conclusion: Shar证明了通过影子虚拟机架构和声明式规范语言可以实现跨运行时、可扩展、高性能且高精度的动态污点分析，为解释型语言的动态分析提供了通用化解决方案。

Abstract: Dynamic taint analysis (DTA) for interpreted languages like JavaScript and Python requires three capabilities: observing host-runtime operations, maintaining parallel taint states, and defining how taint propagates. Existing systems couple these capabilities within an instrumentation mechanism -- source-rewriting or engine-native -- either incurring high runtime overhead or demanding engine-specific embeddings. There is yet to be a runtime-independent abstraction of a general DTA that separates taint semantics and state transitions from how a host runtime observes and executes them.
  We set out to develop a DTA engine that is extensible, performant, and accurate. To achieve this, we introduce a Shadow Virtual Machine executing alongside host runtimes that tracks multi-level taint, provenance, and cross-invocation context. We design Mystra, a declarative taint specification language with formal operational semantics. Mystra is designed to be language model friendly, and is equipped with validators enabling trustworthy automated synthesis of rules. Mystra is also the first to express higher-order function taint transfer declaratively. Further, Mystra rules are compiled ahead of time to a binary representation and dispatch in constant runtime.
  We implement our vision into a tool named Shar, which contains a shared core engine and instantiations on three runtimes: V8 in both Node.js and Chromium (embedding), SpiderMonkey (engine), and CPython (language). Accuracy wise, on SecBench.js (493 in-scope CVEs across four CWE categories), our V8 instantiation achieves 95.5% recall with zero false positives on patched-version testing. Regarding performance, the runtime overhead of Shar is only 1.85$\times$ over vanilla Node.js on NodeMedic's benchmarks, and is 22.7$\times$ lower than NodeMedic-FINE on identical workloads, all the while producing 33.2% higher recall in its supported categories.

### [5] [When is LLM-Based Program Reasoning Correct? A Completion Semantics for LLM-Based Code Inference](https://arxiv.org/abs/2607.12490)
*Zhiyuan Liu,Yihe Li,Trevor E. Carlson,Huiyan Wang,Ruijie Meng,Gregory J. Duck*

Main category: cs.PL

TL;DR: 本文提出了一种用于LLM程序推理的补全语义（completion semantics），将不完整程序片段形式化为一个可能的细化空间，并基于补全模型定义存在性推断的正确性。通过生成可执行见证（witness）来具体化支持推断的补全，从而区分合理假设与不现实假设下的推断。


<details>
  <summary>Details</summary>
Motivation: LLM通常在代码片段（而非完整程序）上进行推理，这种推理依赖于对省略代码和上下文的隐性假设，导致推断结果的含义并非绝对，而是取决于补全模型。现有方法缺乏对这种依赖性的形式化描述和验证机制。

Method: 1. 提出补全语义，将不完整程序形式化为可能细化的空间；2. 定义存在性推断的正确性，即存在一个补全模型中的实例能够证实现象；3. 实现见证生成工作流，通过构造可执行的细化来具体化支持推断的补全。

Result: 在真实世界的LLM生成的bug报告和程序分析任务上的评估表明，见证生成能够有效区分由合理补全支持的推断和需要不现实假设的推断。

Conclusion: 补全语义为验证不完整程序上的LLM推理提供了一种实用机制，通过见证暴露推断所依赖的假设，有助于提高LLM生成报告的可信度和可解释性。

Abstract: Due to token and cognitive limits, Large Language Models (LLMs) typically perform program reasoning over incomplete code fragments/prompts rather than complete programs. Such reasoning therefore must rely on {assumptions about omitted code and context. As a result, the meaning of an inference over a program fragment is not absolute, but depends on an implicit completion model describing how the fragment may be refined into a complete program. In this paper, we introduce completion semantics for LLM-based program reasoning. We formalize incomplete programs as denoting a space of possible refinements and define the correctness of existential inferences relative to a completion model. Under this view, a reported bug is correct whenever there exists a completion within the model that witnesses the bug. This perspective explains why many LLM-generated reports are neither simply correct nor incorrect, but instead depend on assumptions about omitted context. We have instantiated our approach in the form of a witness-generation workflow that concretizes completions underlying an inference by constructing executable refinements of the original program fragment. Witnesses serve both as evidence for existential claims and as a mechanism for exposing the assumptions required to support them. We evaluate our approach on real-world LLM-generated bug reports and program-analysis tasks. Our results show that witness generation effectively distinguishes inferences supported by plausible completions from those requiring unrealistic assumptions, providing a practical mechanism for validating reasoning over incomplete programs.

</details>
