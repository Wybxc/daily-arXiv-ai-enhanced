### [1] [A Rowhammer attack on Fil-C's software capabilities](https://arxiv.org/abs/2610.33748)
*Amir Naseredini,Suhas Viswanath,Martin Berger*

Main category: cs.PL

TL;DR: 提出一种面向Rowhammer故障的概率小步操作语义，抽象掉DRAM内部细节，用概率故障模型刻画位翻转，并形式化验证物理隔离防御的语义保证。


<details>
  <summary>Details</summary>
Motivation: Rowhammer可通过重复访问攻击行使邻近受害行发生位翻转，违背了"读写某一内存位置不影响其他位置"的语言语义基本假设。然而目前缺乏将Rowhammer故障与程序行为联系起来的通用形式化框架，难以严格论证各类防御措施的有效性及其提供的程序级保证。

Method: 为一个理想化命令式语言建立概率小步操作语义，语义在高层抽象DRAM内部结构与半导体物理。以通用概率故障模型作为参数，通过在指定受害区域内读写时赋予位翻转概率来刻画Rowhammer式故障，并借助概率计算的标准单子结构将分布传播到整个程序。作为案例，形式化物理隔离（physical separation）防御。

Result: 证明了一个与分布无关的语义坍缩定理：对任意有限执行（包括终止与非终止执行的前缀），概率Rowhammer语义在受保护投影下等于相应无Rowhammer执行的Dirac分布。此外给出了观测参数化的安全信息流刻画。

Conclusion: 该工作首次为Rowhammer故障与程序行为提供统一的形式化语义框架，使防御措施的有效性与程序级保证可被严格推理；物理隔离被证明在任意故障分布下完全消除可观测偏差，并可扩展到安全信息流分析。

Abstract: Rowhammer is a hardware vulnerability in dynamic random-access memory (DRAM) in which repeated accesses to one or more aggressor rows can induce bit-flips in nearby victim rows. This phenomenon violates a core assumption of conventional programming language semantics: that reading from or writing to one memory location does not modify others. Despite the security importance of this phenomenon, there is no widely established formal framework connecting Rowhammer faults with program behaviour. This makes it difficult to reason rigorously about the efficacy of proposed Rowhammer defences and the program-level guarantees they provide. To address this gap, we present a probabilistic small-step operational semantics for an idealised imperative language subject to Rowhammer-style faults. The semantics is high-level in that it abstracts from DRAM internals and semiconductor physics. A general probabilistic fault model parameterises the semantics, representing Rowhammer-style faults by assigning probabilities to bit-flips during read or write operations within a specified victim region. The resulting distributions are propagated through programs using the standard monadic structure of probabilistic computation. As a case study, we formalise physical separation, a well-known defence that places program variables sufficiently far apart in physical memory that an access to one variable cannot disturb another. We prove a distribution-independent semantic collapse theorem: for every finite execution, including prefixes of terminating and non-terminating executions, the protected projection of the probabilistic Rowhammer semantics is the Dirac distribution of the corresponding Rowhammer-free execution. Furthermore, we develop an observation-parametric account of secure information flow.

### [2] [PastaLean: Deterministic transpilation from Python to Lean for Verification](https://arxiv.org/abs/2610.34205)
*Anirudh Gupta,Petros Markopoulos,Siddhartha Gadgil*

Main category: cs.PL

TL;DR: PastaLean：基于Python AST的确定性Python→Lean翻译系统，配有类型推断引擎TypeInfer，用于验证Python（尤其是AI辅助代码）。


<details>
  <summary>Details</summary>
Motivation: AI生成的Python辅助代码缺乏可靠验证手段；现有翻译到证明助手的过程不确定且缺少对无类型Python的静态类型支持。

Method: 通过Python抽象语法树做确定性翻译，每个程序生成“可证明孪生”（供Lean验证工具推理）与“可运行孪生”（提供快速正确的计算支持）；并引入TypeInfer静态类型推断引擎。

Result: LeetCode与HumanEval+覆盖超92%，LiveCodeBench真值文件超98%；各数据集数值测试用例通过率至少97%，HumanEval+与LiveCodeBench达100%；TypeInfer在TypeEvalPy静态排行榜居首，在仓库级TypyBench上优于所有对比工具。

Conclusion: PastaLean与TypeInfer为Python代码的Lean形式化验证提供了可行且表现优异的方案，在多个基准上取得领先结果。

Abstract: We present PastaLean, an extensible system for deterministic translation from Python to Lean via the Abstract Syntax Tree of Python. This allows for verification of Python code, especially auxiliary code used by AI. Every program is translated into a provable twin written in the form Lean's verification tooling can reason about, and a runnable twin that gives a fast and correct computation support. We also introduce our Type Inference engine TypeInfer which provides static typing support for untyped Python code. Our tool provides coverage of more than 92\% for LeetCode and HumanEval\textsuperscript{+} and more than 98\% for LiveCodeBench ground truth Python files. Further, at least 97\% of each dataset's (numerical) test cases pass, with 100\% on HumanEval\textsuperscript{+} and LiveCodeBench. The TypeInfer engine is the best-scoring tool on the TypeEvalPy static leaderboard, and on a repository-level TypyBench benchmark it scores above every competing repository-level inference tool.

</details>
