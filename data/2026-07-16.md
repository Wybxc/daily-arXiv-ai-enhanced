### [1] [Executable JavaScript as a Checkable Specification Language: A JS-SAM Case Study on SysMoBench](https://arxiv.org/abs/2607.13092)
*Jean-Jacques Dubray*

Main category: cs.PL

TL;DR: 本文通过SysMoBench基准测试和JS-SAM后端，比较了大型语言模型用TLA+和JavaScript（SAM模式）生成形式化规范的能力。研究发现：规范是否符合真实系统是唯一能区分模型性能的维度；在控制变量后，规范契约（而非语言）决定保真度；最小契约只能转录而非推导语义，在复杂协议（如Raft共识）中理解协议本身才是难点。JavaScript可作为TLA+验证的补充规范基板。


<details>
  <summary>Details</summary>
Motivation: 探究大语言模型能否为真实系统编写忠实的正式规范，以及规范语言（罕见的形式语言TLA+ vs. 主流语言JavaScript）对规范质量的影响，同时分离语言、规范契约和提示三个混杂变量进行受控比较。

Method: 构建SysMoBench基准（四阶段评分，最后一阶段回放系统执行轨迹验证），新增JS-SAM后端（JavaScript实现SAM模式，语义镜像TLA+）；对四个前沿模型、三个系统（OS自旋锁、分布式锁服务、Etcd Raft共识）进行受控实验，支持反例驱动修复。

Result: 1) 规范与真实系统的一致性（回放检测）是唯一能区分模型能力的阶段，内部一致性和表面正确性不够；2) 控制变量后，规范契约（specification contract）而非语言决定保真度，JavaScript按TLA+转移关系格式编写与TLA+同样忠实；3) 最小契约只能转录无法推导语义，在Raft共识规模下理解协议本身是瓶颈。

Conclusion: 可执行的JavaScript规范可作为可检查的规范基板，补充而非取代TLA+提供的验证能力；该研究作为案例展示了如何分离混杂变量进行公平比较。

Abstract: Can large language models write faithful formal specifications of real systems, and does it matter whether they write in a formal language they have seen rarely or in a mainstream language abundant in their training data? We study this on SysMoBench, which grades a generated specification in four phases, the decisive one replaying execution traces captured from the running system. We add JS-SAM, its first non-formal backend, in which a specification is executable JavaScript written in the SAM pattern, a pattern whose semantics mirror TLA+, and run a controlled comparison that separates three variables an ordinary head-to-head entangles: the language, the specification contract (the shape the model must fill), and the prompt. The study spans four frontier models and three systems (an operating-system spinlock, a distributed lock service, and the Etcd Raft consensus implementation), with counterexample-driven repair. Three findings emerge. First, conformance against the real system is the only phase that discriminates among models; internal consistency is inexpensive to satisfy, and a specification that looks right is not thereby right. Second, once the comparison is drawn like for like, the specification contract, not the language, governs fidelity: JavaScript in the shape of the TLA+ transition relation is as faithful as TLA+. Third, a minimal contract carries transcription but not semantic derivation: at consensus scale the difficulty becomes understanding the protocol, which no contract shape and no language supplies. We frame executable JavaScript as a checkable specification substrate that complements, rather than replaces, the verification TLA+ provides, and present the study as a case study.

### [2] [Decomposable Type Highlighting for Bidirectional Type and Cast System](https://arxiv.org/abs/2607.13727)
*Max Carroll,Anil Madhavapeddy,Patrick Ferris*

Main category: cs.PL

TL;DR: 本文探索为程序员提供交互式界面，解释静态类型和动态类型转换的推导过程，旨在改进静态和动态类型错误的调试。作者在双向系统中定义了可分解高亮系统的数学基础，并展示了如何通过动态类型转换系统传播这些信息。在渐进类型化的Hazel语言中实现了原型，包含基于Web的用户界面，强调了类型级调试的重要性。


<details>
  <summary>Details</summary>
Motivation: 改进静态和动态类型错误的调试体验，为程序员提供类型推导过程的交互式解释界面。

Method: 在双向类型系统中定义可分解高亮系统的数学基础，通过动态类型转换系统传播类型信息，并在Hazel语言中实现基于Web的原型系统。

Result: 在渐进类型化Hazel语言中实现了包含Web界面的原型系统，能够交互式展示类型推导和类型转换过程。

Conclusion: 交互式类型级调试界面对于理解类型错误具有重要意义，可分解高亮系统为类型调试提供了可行的理论基础和实践方案。

Abstract: We explore how to provide programmers with an interactive interface for explaining the process by which static types and dynamic casts are derived, with the goal of improving the debugging of static and dynamic type errors. To this end, we define mathematical foundations for a decomposable highlighting system within a bidirectional system and show how these can be propagated through dynamic types in a cast system. Our prototype implementation in the gradually typed Hazel language includes a web-based user interface, through which we highlight the importance of type-level debugging.

### [3] [Generative Compilation: On-the-Fly Compiler Feedback as AI Generates Code](https://arxiv.org/abs/2607.13921)
*Niels Mündler-Sasahara,Hristo Venev,Dawn Song,Martin Vechev,Jingxuan He*

Main category: cs.PL

TL;DR: 提出"生成式编译"（Generative Compilation）方法，通过设计一种名为sealor的轻量级语法引导变换，将部分程序转换为完整程序以利用标准编译器提供诊断反馈，在Rust代码生成中显著减少编译错误并提升功能正确性。


<details>
  <summary>Details</summary>
Motivation: 丰富静态语义的语言（如Rust）能为AI生成代码提供更强保障，但其严格性使生成更困难。现有编译器仅在生成后提供反馈，不指导中间生成步骤；受约束解码需要白盒模型访问且语义约束实现成本高。因此需要一种在生成过程中就能获得编译器反馈的方法。

Method: 提出sealor：一种轻量级、主要基于语法引导的变换，将部分程序转换为完整程序，使标准编译器能够对其进行诊断。该方法保证可能完成的部分程序不会被拒绝，同时保留足够代码上下文以尽早捕获真正的死胡同。在类Rust核心演算中证明其性质（在Lean中机械化），并扩展到真实Rust的部分程序检查器。

Result: 在具有挑战性的仓库级Rust编码任务上（覆盖前沿黑盒模型和开源模型），生成式编译相比标准后生成反馈减少了非编译输出并提升了功能正确性。该方法能在接近错误源头处早期检测广泛错误，减少错误级联并实现聚焦诊断。

Conclusion: 生成式编译是使编译器成为AI辅助编程的一等公民的一步，使其在生成过程中活跃而非仅在生成后作为检查手段。

Abstract: Languages with rich static semantics, such as Rust, provide stronger guarantees for AI-generated code, but their strictness makes generation more difficult. Off-the-shelf compilers can provide useful feedback post-generation, but does not guide intermediate generation steps, such as those during autoregressive LLM decoding. Constrained decoding intervenes earlier by rejecting invalid tokens during sampling, but requires white-box model access and costly reimplementation for semantic constraints.We introduce generative compilation, the first approach to obtaining compiler feedback on partial programs during generation. The core technical device is a sealor: a lightweight, mostly syntax-guided transformation that converts partial programs into complete ones that standard compilers can diagnose. It is designed such that possible-to-complete partial programs are never rejected, while preserving enough code context to catch genuine dead ends early. We construct such a sealor on a core Rust-like calculus and prove that it satisfies these properties, all mechanized in Lean. We extend it to the first partial-program checker for real Rust. We evaluate our method on challenging repository-level Rust coding tasks, across both frontier black-box and open-weight models. We show that generative compilation reduces non-compiling outputs and improves functional correctness, relative to standard post-generation feedback. It does so by detecting a broad range of errors close to their source and early during generation, thereby reducing errors cascades and enabling focused diagnostics. More broadly, generative compilation is a step toward making compilers a first-class citizen of AI-assisted programming active during generation, rather than a separate post-generation check.

</details>


### [4] [Backpropagation for Effectful Languages I: Finite Probability and Discrete Output Algebraic Effects](https://arxiv.org/abs/2607.13935)
*Diogo Simm,Fernando Lucatelli Nunes,Matthijs Vákár*

Main category: cs.PL

TL;DR: 本文在组合同态自动微分（CHAD）框架下，为离散概率程序定义了反向模式自动微分，核心创新在于让余切线不仅流经确定性计算，还流经概率结构本身，并通过范畴逻辑关系论证证明了其正确性。该构造可推广到有限集非确定性、异常和writer风格累积等代数效应。


<details>
  <summary>Details</summary>
Motivation: 现有CHAD框架主要处理确定性程序，缺乏对概率程序的自动微分支持。概率程序的微分需要处理概率结构本身的梯度流动，这超出了传统AD的范畴。

Method: 以有限原子分布单子为案例研究，在CHAD框架下将其视为程序的结构保持变换，由指称语义指导。定义反向模式代码变换，通过范畴逻辑关系论证证明其正确性。

Result: 成功为离散概率程序定义了正确的反向模式AD变换，并证明该构造可复用推广到有限集非确定性（如fork-join并行）、异常和writer风格累积（如高维向量就地累积）等离散输出代数效应。

Conclusion: 本文为将CHAD扩展到更丰富的概率语言及其他带处理器的代数效应奠定了基础。

Abstract: We analyse reverse-mode automatic differentiation (AD) for discrete probabilistic programs. Our construction is formulated in the framework of Combinatory Homomorphic Automatic Differentiation (CHAD), treating AD as a structure-preserving transformation of programs, guided by a denotational semantics.
  The main case study is the finite atomic distribution monad, whose computations have finite support and differentiable weights. The key point is that differentiating probabilistic programs requires cotangents to flow backwards not only through deterministic computations, but also through the probabilistic structure itself. We define the corresponding reverse-mode code transformation and prove its correctness, for handled real-output programs, by a categorical logical-relations argument.
  Although the paper focuses on finite discrete probability, the construction gives a reusable pattern for differentiating discrete-output algebraic effects, including finite multiset non-determinism (e.g., from fork-join parallelism), exceptions, and writer-style accumulation (e.g., for in-place accumulation of high-dimensional vectors). More broadly, we view this work as a foundational step towards extending CHAD to richer probabilistic languages and to other algebraic effects with handlers.

</details>
