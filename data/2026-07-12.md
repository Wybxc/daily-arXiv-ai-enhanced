### [1] [SPL: Orchestrating Workflows with Declarative Deterministic-Probabilistic Composition](https://arxiv.org/abs/2607.07727)
*Wen G. Gong*

Main category: cs.PL

TL;DR: SPL是一种声明式语言，统一了确定性计算（SOLVE/ASSERT）与概率性计算（GENERATE/EVALUATE），可在本地节点、云API和分布式网格上无修改运行。通过78个配方和1200次实验验证，求解器方案达到82-93%的机器验证正确率，主要失败模式是求解器错误而非格式不合规。


<details>
  <summary>Details</summary>
Motivation: 现有框架将LLM调用（AutoGen、CrewAI、LangGraph）与符号计算工具（SymPy、SageMath、Lean）分离，缺乏统一的声明式规范。作者希望设计一种语言，能够在一个规范中组合确定性和概率性计算模式，并支持跨平台无缝部署。

Method: 设计SPL声明式语言，提供GENERATE/EVALUATE（概率计算）和SOLVE/ASSERT（确定性计算）两类原语，共享语法、变量绑定和运行时路由。模型和验证器的选择推迟到调用时，实现跨平台（Ollama、OpenRouter、Anthropic、Momagrid）无修改运行。通过78个配方的cookbook和1200次控制实验（10模型×20问题×2臂×3重复，20问题跨6个难度等级）进行验证。

Result: 求解器臂达到82-93%的机器验证正确率（sonnet-4-6: 85%，gemma4:e2b: 93%），而纯LLM臂仅测量无数学验证的输出生产。后端难度梯度显现（SymPy 78%，Sage 54%），主要失败模式是solver_error（内核拒绝表达式）而非格式不合规。

Conclusion: SPL成功统一了确定性和概率性计算模式，在数学推理任务上相比纯LLM方法显著提升了可验证的正确性。研究揭示了不同符号后端之间的性能差异，并指出求解器错误是主要瓶颈。

Abstract: We present SPL (Structured Prompt Language), a declarative language that composes deterministic and probabilistic computation modes in a single specification. While existing frameworks separate these -- orchestration systems (AutoGen, CrewAI, LangGraph) for LLM calls, symbolic tools (SymPy, SageMath, Lean) for computation -- SPL unifies them. It provides GENERATE/EVALUATE for probabilistic computation and SOLVE/ASSERT for deterministic computation, sharing syntax, variable bindings, and runtime routing. A .spl specification runs unchanged across local nodes (Ollama), cloud APIs (OpenRouter, Anthropic), and distributed grids (Momagrid), with model and verifier selection deferred to invocation time.
  We validate SPL through an extensive 78-recipe cookbook and a controlled 1,200-run experiment (10 models x 20 problems x 2 arms x 3 repetitions; the 20 problems span 6 difficulty tiers). The solver arm achieves 82-93% machine-verified correctness (sonnet-4-6: 85%, gemma4:e2b: 93%) while the LLM-only arm measures output production without mathematical verification, making the comparison one of verified correctness against unverified fluency. A backend difficulty gradient emerges (SymPy 78%, Sage 54%), and the dominant failure mode is solver_error (kernel-rejected expressions), not format non-compliance.

### [2] [Environment-Sensitive Lexicographic Disambiguation for Contextual Parsing](https://arxiv.org/abs/2607.07728)
*Alejandro Luis Vaz Mayato*

Main category: cs.PL

TL;DR: 提出了一种基于全局可变上下文的确定性子句消歧算法，通过在非终结符处进行锦标赛式选择，利用增量构建AST时维护的语义状态实现上下文感知的消歧。


<details>
  <summary>Details</summary>
Motivation: 传统的解析树消歧方法多依赖后处理或临时规则，缺乏在解析过程中利用上下文信息进行一致性消歧的机制。

Method: 采用锦标赛式选择过程，在非终结符处对竞争推导进行筛选；在增量AST构建过程中维护语义状态，使早期决策影响后续消歧；基于文档环境而非临时规则实现句法消歧。

Result: 能够建模先前构造与同一非终结符的不同推导之间的复杂关系，实现一致且程序化的消歧。

Conclusion: 该上下文感知策略在解析过程中即可完成消歧，避免了后处理的额外开销，并能处理复杂的上下文依赖关系。

Abstract: This paper presents a deterministic algorithm for resolving ambiguity in parse trees using a global mutable context. The proposed method applies a tournament-style selection process to competing derivations at each non-terminal, systematically discarding alternatives whose non-terminal subtrees are not selected by the contextual decision mechanism.
  Unlike approaches that rely on post-processing, the algorithm maintains semantic state throughout incremental Abstract Syntax Tree (AST) building, allowing earlier decisions to influence the resolution of future ambiguities. This context-aware strategy enables consistent and procedural disambiguation after parsing.
  It features syntactic disambiguation based on a document environment instead of relying on ad-hoc rules, thus able to model complex relationships between previous constructs and the different derivations for a same non-terminal.

Abstract: In Haskell, class instance deriving and related mechanisms are used pervasively. This paper proposes an extension to Haskell's existing deriving machinery so that it can operate over composite data types and multi-level type class hierarchies. With this approach, programmers no longer need to write deriving clauses for every data declaration or explicitly enumerate all superclasses in a type class hierarchy.

### [4] [GradInf: Gradient Estimation as Probabilistic Inference](https://arxiv.org/abs/2607.07840)
*Gaurav Arya,Mathieu Huot,Moritz Schauer,Alexander K. Lew,Feras A. Saad*

Main category: cs.PL

TL;DR: 本文提出梯度推理（gradient inference），一种将概率程序的梯度估计问题转化为概率推理问题的新方法，通过耦合（coupling）和分解（factorization）两种统计操作实现形式化归约。基于此设计了GradInf系统，利用信息流类型系统实现高阶概率程序的源到源变换，支持自动化和可验证的梯度估计器构建，在多个案例中达到最优性能。


<details>
  <summary>Details</summary>
Motivation: 概率程序的梯度估计在科学计算中有广泛应用，但面临高维积分、离散随机选择和复杂随机依赖等难题，现有方法难以兼顾效率和普适性。

Method: 将梯度估计问题形式化归约为一个概率推理问题，通过耦合和分解两个统计操作对输入概率程序进行变换；基于指称语义证明变换的可靠性；利用信息流类型系统将随机选择分解并部分求值，支持自动化实现。

Conclusion: 梯度推理为概率程序的梯度估计提供了一种通用且可验证的形式化框架，借助概率推理的丰富工具箱，能够设计出更优的梯度估计器。

Abstract: Gradient estimation -- the task of computing the gradient of the expected value of a probabilistic program -- has diverse applications in scientific computing, but is notoriously difficult because of issues such as high-dimensional integration, discrete random choices, and complex stochastic dependencies. This article introduces gradient inference, a new approach to developing sound and efficient gradient estimators for probabilistic programs. Gradient inference rests on a formal reduction from a gradient estimation problem to a closely related probabilistic inference problem, whose solution can be differentiated to obtain a gradient estimator. This inference problem is obtained by applying two powerful statistical operations -- coupling and factorization -- to the input probabilistic program. Our reduction lets us leverage the rich toolkit of probabilistic inference algorithms to design novel gradient estimators that extend and improve upon existing methods.
  We introduce GradInf, a probabilistic programming system that facilitates the sound and automated implementation of gradient inference. GradInf is centered around programmable source-to-source transformations for coupling and factorizing higher-order probabilistic programs, whose soundness is proven in terms of a denotational semantics. Key to our development is the use of information-flow typing to allow random choices in a probabilistic program to be factored out and partially evaluated, which improves our ability to deploy sophisticated probabilistic inference algorithms. The resulting system offers practitioners a principled framework for designing gradient estimators. We apply GradInf to several challenging case studies, showing that it can express prominent gradient estimators from the literature and enables the construction of new state-of-the-art estimators that outperform the best existing baselines.

### [6] [ESBMC-Arduino: Closing the Deployment Gap for Formal Verification of Open-Hardware PLCs](https://arxiv.org/abs/2607.08550)
*Pierre Dantas,Lucas Cordeiro,Waldir Junior*

Main category: cs.PL

TL;DR: 本文指出将IEC 61131-3验证工具直接应用于低端微控制器（如Arduino）存在语义鸿沟：验证器假设无限整数模型，而实际硬件使用16位字长和有限分辨率ADC。这导致44%的假警报（54/123），掩盖真实缺陷。作者提出硬件忠实验证方法，通过硬件抽象层（HAL）描述符和输入范围约束，消除了所有假警报，并成功检测到真实宽度相关缺陷。


<details>
  <summary>Details</summary>
Motivation: 现有IEC 61131-3开源验证器（如ESBMC-PLC）基于理想化的无限整数和抽象扫描周期模型进行安全性验证，但实际部署在资源受限的MCU（如8位AVR Arduino）上使用16位字和有限分辨率ADC。这种部署鸿沟导致朴素位宽感知验证不可靠：检查16位溢出时因未建模硬件输入约束而产生大量假警报，同时可能遗漏真实缺陷（如溢出静默抑制安全动作）。

Method: 提出硬件忠实验证方法：1）声明式硬件抽象层（HAL）描述符，包含位宽、ADC/PWM分辨率、I/O绑定等参数；2）将算术运算解释为目标位宽，并将输入约束到硬件可实现范围的正确降级（lowering）语义。基于Arduino实现ArduinoTool，从官方核心提取HAL参数，在ESBMC梯形图（LD）前端实现输入范围模型。

Result: 在123个真实程序语料库上，HAL标注器消除了全部54个假警报（100%消除率），同时保留了稳健性证明；在受控语料库中成功检测到罕见的位宽相关缺陷，并生成可实现的见证（witness）。

Conclusion: 硬件忠实验证对于可信的ICS安全分析至关重要，必须同时建模计算语义（有限位宽算术）和物理约束（传感器输入范围），否则验证结果要么产生空泛的假警报，要么遗漏危险的实数缺陷。

Abstract: OpenPLC, Arduino OPTA, CONTROLLINO, and Industrial Shields M-Duino bring IEC 61131-3 to low-cost microcontrollers used in real automation and industrial control system (ICS) security research. Existing open-source verifiers for IEC 61131-3, including ESBMC-PLC, prove safety over an abstract scan-cycle model with idealized unbounded integers. The board artifact runs on a resource-constrained microcontroller unit (MCU) with 16-bit words (8-bit AVR Arduinos), and sensors are read via a finite-resolution analog-to-digital converter (ADC). We show this deployment gap makes naive width-aware verification unsound: across 123 real programs, checking 16-bit overflow without a hardware input model yields 44% false alarms (54/123) and finds no genuine defects, because it explores sensor values no ADC can produce. Since the gap lies where computation meets the physical process - a bounded sensor reading scaled by finite-width arithmetic into an actuation command - an overflow can silently suppress a safety action, such as a high-level alarm. An unbounded input model fabricates alarms that no environment can trigger. We present hardware-faithful verification for IEC 61131-3 on open hardware: a declarative hardware abstraction layer (HAL) descriptor (width, ADC/PWM resolution, I/O binding) and a sound lowering that interprets arithmetic at target width and constrains inputs to hardware-realizable ranges. We instantiate it for Arduino as ArduinoTool, deriving HAL parameters from official cores and realizing the input-range model in the ESBMC Ladder Diagram (LD) frontend. On the 123-program corpus, the HAL annotator eliminates all 54 false alarms while preserving robustness proofs, and a controlled corpus demonstrates the rare width-dependent defects it detects with realizable witnesses.
