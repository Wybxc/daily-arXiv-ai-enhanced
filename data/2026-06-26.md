### [1] [Axon: A Synthesizing Superoptimizer for Tensor Programs](https://arxiv.org/abs/2606.26344)
*Akash Kothari,Shaowei Zhu,Daniel Kroening,Chungha Sung*

Main category: cs.PL

TL;DR: Axon是一个面向AI加速器的张量程序综合超优化器，通过程序合成自动生成目标指令，并探索语义等价的程序变体以经验性选择最佳内核。它利用SMT over unbounded tensors保证代数变换的语义正确性，并通过硬件约束的tiling配置搜索和算子融合来最小化内存流量。


<details>
  <summary>Details</summary>
Motivation: 为AI加速器编写高性能内核需要深层专业知识（tiling、指令选择、数据布局、算子融合），给程序员带来沉重负担。现有方法依赖手工编写的重写规则，缺乏自动化和语义保证。

Method: 1) 使用程序合成从语义规范自动生成目标指令；2) 通过计算图传播算子进行代数变换，并用SMT over unbounded tensors保证语义等价性；3) 将张量操作lower到目标ISA指令；4) 结合硬件描述探索tiling配置；5) 融合算子和指令以最小化内存流量。

Result: Axon能够自动生成高性能内核，无需手工编写重写规则，并通过经验性搜索找到最佳程序变体。

Conclusion: Axon展示了结合程序合成、SMT验证和硬件感知搜索可以显著降低为AI加速器编写高性能内核的专家负担，实现自动化内核优化。

Abstract: Writing high performance kernels for AI accelerators requires deep expertise in tiling, instruction selection, data layout, and operator fusion placing a significant burden on programmers. In this paper, we focus on tile based AI accelerator programs and present Axon, a synthesizing superoptimizer for tensor programs: it uses program synthesis to automatically generate target instructions from semantics specifications, and explores semantically equivalent program variants to select the best performing kernel empirically. Axon discovers algebraic transformations by propagating operators through computation graphs and uses SMT over unbounded tensors to guarantee that all transformations preserve semantics without requiring hand crafted rewrite rules. It then lowers tensor operations to target ISA instructions, explores tiling configurations constrained by hardware descriptions, and fuses operators and instructions to minimize memory traffic.

### [2] [A Typestate Approach to Purpose-aware Programming](https://arxiv.org/abs/2606.26386)
*Joan Montas,Samuel Dodson,Anitha Gollamudi,Matteo Cimini*

Main category: cs.PL

TL;DR: 本文提出PurPL语言，利用类型状态（typestate）来推理敏感数据的使用目的，并通过形式化类型系统和实现类型检查器来验证数据使用合规性。


<details>
  <summary>Details</summary>
Motivation: 现有文献在编译时保证数据按预期目的使用方面成果有限，缺乏对敏感数据用途进行编译时推理的有效手段。

Method: 基于类型状态（typestate）机制，将敏感数据类型的状态定义为数据可使用目的的集合，该集合可在运行时动态变化。设计了面向对象语言PurPL，包含形式化类型系统，并实现了类型检查器。

Result: 通过示例展示了PurPL的用法，并在多种处理敏感数据的编程场景上进行了类型检查实验。

Conclusion: PurPL能够通过类型状态系统在编译时推理数据使用目的，为敏感数据的使用合规性提供编译时保证。

Abstract: Real-world applications often require verification that sensitive data is being used for their intended purpose. However, existing literature offers limited results regarding compile-time guarantees in this domain. In this paper, we explore the use of typestate to reason about the purpose of data. In typestate, types have a state, which can transition to other states in the style of automata. In our approach, the state of the type of sensitive data is defined as the set of purposes for which the data can be used. This set can grow or shrink at runtime as purposes can be added or removed during execution.
  In this paper, we have developed PurPL, an object-oriented programming language that features a typestate system that is capable of reasoning about purposes and data usage compliance according to them.
  We give an overview of PurPL through examples and present a formal type system. We have also implemented PurPL's type checker, and we report on our experiments with type checking various programming scenarios that handle sensitive data.

### [3] [Compiler-Driven Approximation Tuning for Hyperdimensional Computing](https://arxiv.org/abs/2606.26547)
*Xavier Routh,Abdul Rafae Noor,Akash Kothari,Zheyu Li,Mahbod Afarin,Tajana Rosing,Vikram Adve*

Main category: cs.PL

TL;DR: 本文提出 ApproxHDC，一个用于超维计算（HDC）工作负载中自动识别和应用领域特定近似的框架。它扩展了 HPVM-HDC 编译器基础设施，支持跨 CPU、GPU 及模拟 ReRAM/PCM 加速器的可重定向编译，并通过高效搜索分析在软件和硬件层面找到高影响力的近似配置。


<details>
  <summary>Details</summary>
Motivation: 随着摩尔定律接近物理和经济极限，领域专用方法被越来越多地用于加速机器学习工作负载。超维计算（HDC）作为一种新兴范式，以硬件效率为首要目标，但其近似空间呈指数级增长，需要自动化框架来系统性地探索和利用近似机会。

Method: ApproxHDC 框架扩展了 HPVM-HDC 编译器基础设施，实现跨 CPU、GPU 以及模拟 ReRAM 和 PCM 基础加速器的可重定向编译。它通过高效搜索和分析方法，在指数级增长的近似空间中识别高影响力的近似配置，涵盖软件和硬件两个层面。

Result: ApproxHDC 能够自动化地识别和应用于 HDC 工作负载的领域特定近似，在最小精度损失下实现显著的性能提升，支持多种异构硬件后端。

Conclusion: ApproxHDC 为 HDC 工作负载提供了自动化的近似探索框架，有效利用 HDC 算法对噪声和近似的固有容错性，在异构硬件平台上实现性能与精度的良好权衡。

Abstract: As Moore's law reaches its physical and economic limits, domain-specific approaches are increasingly employed to accelerate machine learning workloads. Hyperdimensional Computing (HDC) represents one such emerging paradigm, offering an alternative to conventional deep learning techniques. Rooted in cognitive models of computation, HDC is designed bottom-up with hardware efficiency as a first-class objective. HDC workloads map naturally to heterogeneous hardware platforms, including CPUs, GPUs, and FPGAs, as well as emerging in-memory computing technologies such as Resistive RAM (ReRAM) and Phase-Change Memory (PCM). HDC algorithms are intrinsically tolerant to noise and approximation, enabling substantial performance gains with minimal accuracy loss. In this work, we introduce ApproxHDC, a framework for automated identification and application of domain-specific approximations in HDC workloads. ApproxHDC extends the HPVM-HDC compiler infrastructure to enable retargetable compilation across diverse hardware backends, including CPUs, GPUs, and simulated ReRAM and PCM-based accelerators. The space of possible approximations is exponentially large; ApproxHDC employs efficient search and analysis to navigate it and identify high-impact configurations spanning both software and hardware levels.

### [4] [Mostly Automatic Translation of Language Interpreters from C to Safe Rust](https://arxiv.org/abs/2606.27122)
*Bo Wang,Brandon Paulsen,Joey Dodds,Daniel Kroening,Umang Mathur,Prateek Saxena*

Main category: cs.PL

TL;DR: Reboot 是一种将 C 语言解释器程序自动或半自动翻译为安全 Rust 的技术，通过特征分解和多智能体架构，成功翻译了 6 个 6k-23k 行代码的解释器，仅需 1-11 次人工干预，100% 通过原测试集，62%-92% 通过盲测验证集，并消除了堆溢出和释放后使用等内存漏洞。


<details>
  <summary>Details</summary>
Motivation: 将 C 程序翻译为安全 Rust 面临类型约束、所有权和借用规则等显著差异的挑战，而解释器程序常处理不受信任输入且易受内存相关漏洞影响，因此迫切需要自动化翻译技术。

Method: 提出 Reboot 技术，包含两个核心思想：(1) 特征分解：按程序特征将翻译分解为一系列里程碑，每个里程碑都是完整可测试的程序，从最简版本开始逐步恢复特征，每一步都经过验证；(2) 多智能体架构：通过自动化验证和反馈协调不可靠的编码智能体，使长流程翻译保持正轨，最小化人工干预。

Result: 成功将 6 个 6k-23k 行 C 代码的解释器翻译为安全 Rust，仅需 1-11 次人工干预；所有翻译 100% 通过原测试集，62%-92% 通过盲测验证集；消融实验表明特征分解相比单独使用多智能体翻译，在验证测试集上提升了 6%-20% 的通过率。

Conclusion: Reboot 能够有效地将真实世界的解释器从 C 翻译为安全 Rust，消除内存漏洞，且特征分解显著提升了翻译的正确性。

Abstract: Translating C programs to safe Rust is challenging owing to significant differences in typing constraints, ownership, and borrowing rules. Interpreter programs are particularly important targets for such translation, as they often handle untrusted inputs and suffer from memory-related vulnerabilities. We present Reboot, a mostly-automatic technique that translates real-world interpreter programs from C to safe Rust. Using Reboot, we have translated six interpreters ranging from 6k to 23k lines of C code to safe Rust, with each translation requiring only 1 to 11 brief user interventions. All translations pass 100% of the provided test suites, and achieve 62%--92% pass rates on separately created validation tests that were never exposed to the system. A security case study on mujs shows that memory vulnerabilities such as heap buffer overflows and use-after-free present in C are eliminated in the safe Rust translation. Two ideas underpin Reboot. First, feature reduction decomposes the translation by program features, creating a sequence of milestones where each is a complete, testable program; the translation starts from the simplest version and incrementally restores features, with each milestone validated before proceeding. Second, a multi-agent architecture orchestrates inherently unreliable coding agents through automated validation and feedback, keeping long-running translation workflows on track with minimal human involvement. An ablation study confirms that feature reduction improves translation correctness compared to using multi-agent translation alone, with 6%--20% improvements in pass rates on validation test suites.

</details>


### [5] [Welterweight Go: Boxing, Structural Subtyping, and Generics (Extended Version)](https://arxiv.org/abs/2606.27138)
*Raymond Hu,Julien Lange,Bernardo Toninho,Philip Wadler,Robert Griesemer,Keith Randall*

Main category: cs.PL

TL;DR: 本文提出了WG（Weightweight Go）作为Go语言的核心模型，涵盖了底层类型、类型联合、类型集合和泛型方法等关键特性，并设计了LWG低级语言来建模Go的运行时机制（如原始结构体值与携带运行时类型信息的接口值的区别）。通过类型导向的编译从WG到LWG，展示了在不依赖静态单态化、无需运行时代码生成且兼容独立编译的前提下，如何利用运行时类型转换和适配器方法处理结构子类型、泛型与运行时基础设施之间的复杂交互。


<details>
  <summary>Details</summary>
Motivation: Go语言结合了泛型之间的结构子类型与非统一运行时表示的类型，给语言形式化带来了重大挑战，现有工作未能涵盖底层类型、类型联合、类型集合以及泛型方法等关键特性，因此需要建立更完整的核心模型来形式化这些特性。

Method: 1) 设计了WG核心模型，捕获Go的底层类型、类型联合、类型集合及泛型方法；2) 设计了LWG低级语言，建模Go的运行时机制（原始结构体值与带RTTI的接口值的区别）；3) 给出了从WG到LWG的类型导向编译策略，使用运行时类型转换和适配器方法，而非静态单态化。

Result: 提出的编译策略能够处理结构子类型、泛型与Go运行时基础设施之间的复杂交互，同时满足Go的重要设计和实现目标：兼容独立编译，且无需运行时代码生成。

Conclusion: 该工作填补了Go语言形式化的空白，提供了一种不同于静态单态化的编译方案，能够更自然地处理Go的结构子类型与泛型组合，为Go语言的未来特性（如泛型方法）提供了理论基础和实现指导。

Abstract: Go's unique combination of structural subtyping between generics and types with non-uniform runtime representations presents significant challenges for formalising the language. We introduce WG (Welterweight Go), a core model of Go that captures key features excluded by prior work, including underlying types, type unions and type sets, and proposed new features, such as generic methods. We also develop LWG, a lower-level language that models Go's runtime mechanisms, notably the distinction between raw struct values and interface values that carry runtime type information (RTTI). We give a type-directed compilation from WG to LWG that demonstrates how the proposed features can be implemented while observing important design and implementation goals for Go: compatibility with separate compilation, and no runtime code generation. Unlike existing approaches based on static monomorphisation, our compilation strategy uses runtime type conversions and adaptor methods to handle the complex interactions between structural subtyping, generics, and Go's runtime infrastructure.

</details>
