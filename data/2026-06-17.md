### [1] [ANEForge: Python for direct computation on the Apple Neural Engine](https://arxiv.org/abs/2606.17090)
*Spencer H. Bryngelson*

Main category: cs.PL

TL;DR: ANEForge是一个Python包，可直接编程苹果神经引擎（ANE），无需通过CoreML。它通过编译惰性张量图（包含58个融合算子和19个原生桥接算子）为单一ANE程序，实现推理、训练（前向、反向、优化器更新）等功能。小融合程序约90μs完成调用，接近引擎70μs的程序调度下限；预训练ResNet-18前向推理端到端0.33ms。支持int8/int4量化、稀疏权重、融合注意力等特性，面向macOS 14+的Apple Silicon设备。


<details>
  <summary>Details</summary>
Motivation: Apple Neural Engine（ANE）在生产环境中仅能通过CoreML访问，而CoreML将ANE视为可调度选项而非必要配置，导致模型可能静默运行在CPU或GPU上。研究者希望绕过CoreML的限制，直接编程ANE以充分利用其固定功能神经加速器的性能潜力。

Method: ANEForge通过编译一个由58个融合算子和19个原生桥接算子构建的惰性张量图，生成单一ANE程序。该程序通过与Apple内部框架相同的ANE守护进程和内核驱动栈进行调度。支持流式int8/int4量化权重和稀疏权重、融合注意力机制、跨步骤保持解码器和优化器状态驻留，以及训练的前向、反向和优化器更新阶段。

Result: 小融合程序调用约90μs（接近引擎70μs调度地板），ResNet-18前向推理端到端0.33ms。ResNet-18、句子编码器和Vision Transformer与框架参考实现进行了端到端验证，Stable Diffusion U-Net验证了前向传播的正确性。

Conclusion: ANEForge成功实现了对ANE的直接编程访问，证明了绕过CoreML层可充分利用ANE的硬件性能，在推理和训练场景下均能达到接近硬件极限的延迟表现。该工具面向macOS 14+的Apple Silicon设备，每次发布均与特定macOS和ANE编译器版本进行验证。

Abstract: ANEForge is a Python package that programs the Apple Neural Engine (ANE), the fixed-function neural accelerator on every recent Apple device, directly and without CoreML. In production the engine is reachable only through CoreML, which treats it as a scheduling option: no configuration requires the ANE, and a model can silently run on the CPU or GPU instead. ANEForge compiles a lazy tensor graph, built from 58 fused operators and 19 native bridge operators, into a single ANE program. The program is dispatched through the same ANE daemon and kernel-driver stack as Apple's internal framework. Beyond inference, the package reaches the engine's native fused attention, streams int8, int4, and sparse weights, keeps decoder and optimizer state resident across steps, and runs the forward pass, backward pass, and optimizer update of training on the engine. A small fused program completes a call in about 90us, near the engine's 70us per-program dispatch floor, and a pretrained ResNet-18 forward runs end-to-end in 0.33ms. ResNet-18, a sentence encoder, and a Vision Transformer run end-to-end against framework references, and a Stable Diffusion U-Net validates its forward pass. ANEForge targets Apple Silicon under macOS 14 and later. Each release is verified against a recorded macOS and ANE-compiler version.

### [2] [Visored: A Controlled-Natural-Language Prover for LLM-Generated Mathematics](https://arxiv.org/abs/2606.17581)
*Xiyu Zhai,Xinyi Chen,Yiping Wang,Runlong Zhou,Liao Zhang,Simon S. Du*

Main category: cs.PL

TL;DR: 本文介绍了一个基于依赖类型、专为LLM（和人类）的数学写作方式设计的定理证明器，其核心是模仿数学自然语言的表面语法和规则驱动的自动化层来填补教科书省略的常规步骤，并能将验证通过的证明重新输出为可检查的Lean文件。初步实验表明，即使没有针对证明器的训练数据，LLM也能在miniF2F基准上有效使用它。


<details>
  <summary>Details</summary>
Motivation: 现有的定理证明系统（如Lean和Rocq）在设计上更偏向形式化专家，与LLM（以及人类）自然书写数学的方式存在差距。作者旨在构建一个更贴近自然数学语言表达、同时能自动填补常规步骤的证明器，以降低LLM使用形式化证明的门槛。

Method: 1) 设计了一个模仿数学自然语言的表面语法（surface）；2) 构建了规则驱动的自动化层，用于自动完成教科书通常会省略的例行程式；3) 将验证通过的证明重新输出为可检查的Lean文件，实现与现有生态的兼容。

Result: 在miniF2F基准测试上，即使没有任何针对该证明器的预训练数据，LLM也能学会有效使用该工具进行定理证明。

Conclusion: 通过面向自然数学表达和自动化常规步骤的设计，可以显著降低LLM使用形式化证明系统的难度，并在标准基准上取得有效结果，同时保持与Lean生态的兼容性。

Abstract: We present a dependent-type-based prover designed around the way LLMs (and humans) tend to write mathematics, complementing existing systems such as Lean and Rocq. Its core design choices are a surface that imitates mathematical natural language and a rule-driven automation layer that closes the routine steps a textbook would omit, so that an accepted proof can be re-emitted as a checked Lean file. Early experiments suggest that, even without any prover-specific training data, LLMs can learn to use it effectively on the miniF2F benchmark. Lean output excerpts: https://github.com/xiyuzhai-husky-lang/visored/

### [3] [Defense-in-Depth Runtime Safety in Move](https://arxiv.org/abs/2606.18064)
*Victor Gao,Wolfgang Grieskamp,Vineeth Kashyap,George Mitenkov,Teng Zhang,Runtian Zhou,Andrea Cappa,Marco Ilardi*

Main category: cs.PL

TL;DR: 本文介绍了Aptos区块链上Move语言执行时的运行时安全检查机制，这些机制作为深度防御策略，在静态验证器可能存在漏洞的情况下，独立验证关键不变量，防止资产损失、权限伪造和链上状态破坏。


<details>
  <summary>Details</summary>
Motivation: Move语言的静态验证逻辑复杂且持续演进，难以避免存在软件漏洞。在实时区块链环境中，任何验证规则的遗漏都可能导致直接的经济损失或状态损坏，因此需要额外的运行时安全层来弥补静态验证的不足。

Method: 在Move虚拟机执行过程中引入独立的运行时安全检查，对类型安全、引用安全等关键不变量进行动态验证，作为对静态验证的补充防御手段。

Result: 实现了对潜在验证器漏洞和恶意字节码的有效防护，确保即使静态验证存在缺陷，运行时仍能捕获并阻止违规行为。

Conclusion: 深度防御的运行时安全检查对于保障Move语言在Aptos区块链上的安全执行至关重要，是静态验证机制的必要补充。

Abstract: Move is a smart-contract language used to execute transactions on the Aptos blockchain. Move programs execute in a sandboxed VM as typed bytecode. The VM statically verifies foundational safety properties like type safety and reference safety at code loading time. In principle, this design gives strong guarantees for Move. However, the static verification logic is complex and continually evolving with the language; like any software, it is not immune to bugs. In a live blockchain setting, a missed rule violation can translate directly into loss of assets, forged authority, or unrecoverable corruption of on-chain state. For this reason, Aptos relies on defense-in-depth runtime safety checks that independently verify the critical invariants during execution, providing protection against latent verifier bugs and malicious bytecode. This paper motivates and describes the runtime safety checks for Move on Aptos.

Abstract: Python dominates AI development, yet the numerical work behind frameworks like PyTorch and NumPy is executed in C, C++, or Rust. The results provide concrete, per-workload guidance for choosing an implementation language in AI systems.
